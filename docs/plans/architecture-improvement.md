# 架构改进回顾

[docs/README.md](../README.md) · [docs/architecture.md](../architecture.md) · [docs/development.md](../development.md) · [ops/README.md](../../ops/README.md)

2026 年实施的架构改进已全部合入 `main`。本页保留这轮改进的目标、原则、各工作流的最终结果与验证边界；逐条用户决定（含被后续修订的条目）只追加在[docs/plans/architecture-improvement/decisions.md](architecture-improvement/decisions.md)，历史进度台账与工作项细节已删除；制定计划时的现状基线归档在 `docs/plans/architecture-improvement/archive/baseline.md`。

正文中的仓库路径均以仓库根为起点；代码证据以“文件 + 符号名”引用，不写行号。

## 1. 目标

在不削弱现有资金安全与审计保证的前提下，降低外部依赖导致的故障面、减少“例外谓词”式维护、让人工处置以证据为中心，并建立可重复的发布、备份与安全基线。

## 2. 原则

1. [AGENTS.md](../../AGENTS.md)的领域不变量全部保持：命令幂等、Serializable 关键事务、追加式事实、结果未知不重发、缓存不决定正确性、冻结策略不改写。
2. 每个交付批次一个阶段提交（依赖相连的工作项合并），按“领域 → 用例/端口 → 存储/外部适配 → HTTP/Web/Worker”落地，同步契约与运维文档。
3. 默认门禁只做静态验证（`just verify`）；行为变更运行受影响范围的已批准测试；其他行为验证、数据删除与线上部署逐项取得用户批准。
4. 先可观测、再改行为：改变运行行为的改动先有能证明效果的指标，并且指标有存储与查看路径。
5. 无预发环境，因此改变运行行为的改动必须带运行时开关与旧路径回退；涉及判定或计数口径的改动先影子运行，差异归零后再切换。
6. 每个工作项写明可度量的验收标准与回退方式；每个结构或错误处理改进都配套防回退门禁。

| 工作流 | 结果 |
| --- | --- |
| 错误分类、指标与采集路径 | 类型化安全错误与 kind/phase 诊断门覆盖 jobs、application、integrations 与 HTTP；HTTP/WebSocket/限流/浏览器信标/外部客户端/数据库事务指标齐全；`127.0.0.1` 指标出口与 Prometheus 采集示例可用；就绪探针按 SQLSTATE 分类，瞬时失败不再永久翻转；影子运行共享框架供各判定口径复用；SLO 与容量目标仍留待真实基线 |

## 4. 验证边界

- **静态门禁**：`just verify`（策略、格式、编译、feature、clippy、wasm、棘轮与文档链接）是每次提交的最低要求，口径见[ci/checks/README.md](../../ci/checks/README.md)。
- **测试**：行为变更随功能维护用例并通过 `just test`；涉及锁、隔离级别、幂等或迁移的断言必须在真实 PostgreSQL 18 上用 `just test-db` 执行。入口与覆盖限制见[docs/development.md#测试](../development.md#测试)。
- **部署**：只部署 GitHub Release 资产，流程与回退边界见[ops/README.md#升级](../../ops/README.md#升级)与[ops/deploy/RECOVERY.md](../../ops/deploy/RECOVERY.md)。
- **性能与并发证据**：读路径、并发形状与按场次队列的比较都来自一次性隔离 PG18 的合成夹具与 `--ignored` 演练，只用于设计取舍，不是生产基线，也不证明线上计划或耗时。
- **运行时观察**：影子差异、SLI 与容量基线、告警处置都由运维手册与模块文档拥有，不在本页重复；本节不构成线上验收证据。浏览器、真实游戏账号与手工冒烟不在本轮的静态与测试门禁范围内。
- 本轮只处理代码与工程体系，不包含线上数据处置；涉及免责的线上操作仍须逐次授权。

## 5. 仍待决定

- 外部告警通道（webhook）、外部存活心跳与 MoogleMail 运维告警通知已实现但默认关闭，启用服务与收件人由用户决定。
- Sent 发送基线的水位模式、就绪审计的 `classified` 模式与处置读侧的 `classified` 模式都保持影子口径，须在观察覆盖一个含 Final 与结算的完整场次周期后由用户显式切换，不自动推进。
- 按场次写队列已覆盖竞价、生命周期与 Admin 排期/草稿 lot，但 Admin 装备录入（world-scoped intake target 需要新的 world → auction 排队入口）、结算/恢复/调度 claim 仍按各自租约与行锁；队列预算与退避尚未做成配置项。Final 阶段同场 p99 若超出 SLO，是否按 lot 拆分队列或调整预算须先用 SLI 采样确认，详见[docs/contracts/database.md#按场次写队列竞价--生命周期--admin](../contracts/database.md#按场次写队列竞价--生命周期--admin)。
- 指标转发拒绝的 CDN 专用来源头待核实真实代理链后再补充；当前只拒绝通用转发头，Caddy 的公网 `/metrics` 404 规则继续保留。
- 主机层基线之外仍有未决项：非本仓库服务的端口暴露、出站地址白名单与配置漂移检测。
- 部署形态与结构评估已出结论，后续若拆分主机或引入配置管理须另行立项。

## 6. 术语

| 术语 | 含义 |
| --- | --- |
| sending 围栏 | 外部写入前持久化的发送状态与 fencing 版本；越过后结果未知只能人工核对，不自动重发 |
| 影子运行 | 新旧路径并行计算、只记录差异，不改变实际结果 |
| 运行时开关 | 持久化在数据库、无需重启即可切换的新旧路径选择；只选路径，不决定业务结果 |
| 水位 | 已完整扫描到的最高远端邮件 ID；只用于缩小扫描范围，不作为发送或收取证明 |
| 论坛游标 | 已处理到的最大帖子 ID 及其所在页；只用于缩小扫描范围，不作为出价证明 |
| 迁移演练 | 用最新备份在隔离的 PostgreSQL 18 上预先执行新迁移并核对，作为无预发环境的替代 |
| 兼容登记 | 每个新迁移在自身事务内写入的 `compatible`/`breaking` 等级；旧程序据此判断自己不认识的版本能否就绪 |
| 心跳打卡 | 定期向外部服务报到，超时未报到即由外部服务告警（死人开关） |
| 外部服务替身 | 由脱敏回放语料驱动的本地 MoogleMail/论坛模拟服务，只用于测试，绝不连接真实账号 |
| 棘轮门禁 | 只允许计数下降、不允许回涨的静态检查 |

业务流程详见[docs/guide/settlement.md](../guide/settlement.md)与[docs/guide/mail-flows.md](../guide/mail-flows.md)。
