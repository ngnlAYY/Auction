## 1. 目标与原则

目标：在不削弱现有资金安全与审计保证的前提下，降低外部依赖导致的故障面、减少“例外谓词”式维护、让人工处置以证据为中心，并建立可重复的发布、备份与安全基线。

原则：

1. [协作规范](../../AGENTS.md)的领域不变量全部保持：命令幂等、Serializable 关键事务、追加式事实、结果未知不重发、缓存不决定正确性、冻结策略不改写。
2. 每个工作项一个主题提交，按“领域 → 用例/端口 → 存储/外部适配 → HTTP/Web/Worker”落地，同步契约与运维文档。
3. 默认门禁仍为 `just verify`；行为测试、数据删除与线上部署都需要用户逐项批准（见[决策记录](#7-决策记录)）。
4. 先可观测、再改行为：每个改变运行行为的阶段，都先有能证明改进效果的指标。

## 2. 现状基线

| 项 | 基线 | 证据 |
| --- | --- | --- |
| 规模 | 约 21.5 万行 Rust；`auction-storage` 5.4 万行、`auction-application` 3.5 万行、`auction-domain` 0.5 万行 | 源码统计 |
| 迁移 | 74 个，三周内累积 | `migrations/postgres` |
| 测试 | 17 个测试函数；CI 有静态、审计、MSRV 与发布构建作业，无测试作业 | `.github/workflows/ci.yml` |
| 外部账号 | MoogleMail 与论坛各一个账号，各自所有请求共用一个 FIFO 间隔门（代码默认 750 ms，线上 MoogleMail 配置 1000 ms），无优先级、无账号级熔断 | `IntervalGate`（`crates/auction-integrations/src/clients/mooglemail/client/security.rs`）；论坛客户端同类默认值 |
| 全量扫描 | 维护每 5 分钟完整扫描 Sent（约 37 页），Read Mail 观察完整扫描已读（约 34 页），上限均为 `maximum_pages`（默认 100） | 线上日志：部署 `68c1b8df` 后维护每轮 120 秒超时 |
| 账号忙 | 战斗页按请求逐个失败，每次保存诊断；诊断目录硬上限 1024 文件 | 2026-11-02 约 2000 次/小时 `account_busy`，旧诊断被全部挤出 |
| 通知量 | 出价被超提醒按 lot、用户与轮次各发一封 MoogleMail，无按收件人合并或限额；失去资格的提醒成批预检退役 | `services/public/watch.rs`；线上 110 条预检退役 |
| 错误可观测 | Worker 有 43 处丢弃错误详情（`Err(_error)`/`Err(_) =>`）；`ApplicationError` 没有安全分类 | `crates/auction-jobs/src/worker` |
| 规则位置 | 资格与状态机散落在存储层：JSON `Value` 字段比较、SQL 推进、数据库函数（迁移 073/074） | `sent_confirmation/snapshot.rs`、`recovery_scheduler`、`settlement_funding/receipt.rs` |
| 时区耦合 | legacy 自寄与装备损失证明用 `to_jsonb(行)` 与快照整行比较（含时间戳），只因 sqlx 连接固定 `TimeZone=UTC` 才成立；其他会话时区下结论翻转 | `legacy_self_proof/mod.rs`、`equipment_loss/proof.rs` |
| 处置语义 | legacy 自寄、装备损失、Admin 判失败、预检退役、人工 Sent 证明各有专用表或谓词，仪表盘/告警/列表分别拼排除条件 | `operations_alert/snapshot/reads.rs` |
| 资产与资金 | 没有定期核对 bot 应持装备与 Armory 实际库存；仅记账模式下没有余额漂移检测 | 无对应端口；`FundingPolicy::observes_cash` |
| 告警通道 | 运维告警经同一游戏账号的 MoogleMail 发送 | `[worker.operations_alert]` |
| 安全暴露 | 发布的 Caddy 模板把 Admin 作为独立公网站点代理，无来源限制；Admin 登录无第二因素；与[架构](../architecture.md#安全边界)“Admin 不应暴露到公网”不一致 | `ops/deploy/caddy/Caddyfile` |
| 密钥轮换 | 每类数据密钥只有单个 key ID，无密钥环与重加密流程 | `auction-config` secrets 模型；CLI 证据导出需保留旧密钥 |
| 备份与保留 | 只有手动 `backup create`；仓库无定时任务模板；`db inventory` 明确不授权归档或删除，表无限增长 | `ops/deploy/systemd`、`apps/auction-cli/README.md` |
| 发布 | CI 每次推送已构建并上传 `release-candidate-<sha>`，但部署仍在本地重建并手工多步执行；部署状态写在服务器 README；无预发环境；生产库与 unit 带 `test` 命名；仓库无 `main`，远端默认分支为 `refactor/dioxus-frontend`，本地 `master` 已过时 | `.github/workflows/ci.yml`、服务器部署记录 |
| 资源 | 每进程固定 16 个数据库连接，不可配置，无饱和指标 | `postgres_store.rs` |

### W1 外部账号调度

| 项 | 内容 | 关键约束 |
| --- | --- | --- |
| W1.0 快速限界 | Read Mail 观察改为有界页数或降频，并与 Sent 维护错开；先确认共享 reader 对完整已读列表的依赖 | 只减少读取；不改变任何证明或业务结果 |
| W1.1 账号忙熔断 | 识别战斗页/冻结后按账号记录 `busy_until`，退避 1→2→5→10 分钟，期间只放行一次探测，其余请求不发网络直接返回 `AccountBusy` | 熔断只在内存限流，不决定业务状态（不变量 5）；写入类在 sending 围栏前被拒 |
| W1.2 诊断去重 | 同一忙碌期只保存首份战斗页；诊断淘汰按类别优先保留写入未知证据 | 不降低 write_unknown 证据保全 |
| W1.3 优先级门 | 分级令牌桶替换 FIFO `IntervalGate`：写入（send/take/return）> 付款与交付证据 > 收件 > 维护 > 观察 > 通知；低优先级保底份额 | 总速率不超过配置间隔；同账号远端写入串行 |
| W1.4 增量扫描 | Sent 与 Read Mail 持久化“已完整扫描到的最高 MID + 时间”水位，常规轮只读新增页；候选早于水位时按候选时间有界回扫；每日一次完整校验扫描 | 水位不作为发送或收取证明；缺失或不连续回退完整扫描 |
| W1.5 证据退避 | 履约证据按年龄指数退避（每分钟逐步放宽到 30 分钟），付款截止前后提高频率 | 不改变付款期限与恢复策略 |
| W1.6 论坛对齐 | 论坛客户端接入同一调度抽象：优先级、写入未知、熔断与指标 | 论坛写入仍按既有未知结果流程，不自动重发 |
| W1.7 通知优先级 | 出价被超提醒保持现有发送规则（不合并、不限额，决策 1），只在 W1.3 中作为最低优先级 | 不改变玩家可见行为 |
| W1.8 配置 | 预算、退避与通知参数进入 `worker.toml`，带中文“可选/必填”注释并同步[配置参考](../../ops/config/README.md) | 默认值不超过当前上限 |

验收（以 W0 指标度量）：稳态外部请求低于配额 30%；维护 p95 低于 60 秒且无预算耗尽；模拟战斗期每个退避间隔不超过 1 次探测、1 份诊断。

### W3 规则上移

统一模式：

```text
storage：按锁序加载 → 类型化快照（结构体，而非 JSON Value）
application/domain：evaluate(snapshot) → 允许 / 阻断项闭集
storage：以快照版本做 CAS 写入；数据库函数保留为最后一道约束
```

| 批次 | 目标 | 现位置 |
| --- | --- | --- |
| W3.1 | 人工 Sent 证明准入（两种准入、时间窗、资金占用） | `sent_confirmation/snapshot.rs` |
| W3.2 | 装备损失处置准入 | `equipment_loss/snapshot.rs` |
| W3.3 | 恢复阶段推进收敛为领域状态机 | `recovery_scheduler/scheduler/advance.rs` |
| W3.4 | Admin 投递动作守卫（目击、退役、迁移表） | `delivery_admin/commands.rs` |
| W3.5 | COD 实收资金化校验（结合 D1 结论） | `settlement_funding/receipt.rs` |
| W3.6 | 履约 claim 一致性校验 | `fulfillment_scheduler/claims.rs` |
| W3.7 | 行快照证明改为时区无关：显式列比较或 UTC 规范化时间，不依赖会话 `TimeZone` | `legacy_self_proof/mod.rs`、`equipment_loss/proof.rs` |

每批验收：业务规则不再以 JSON 下标表达；Rust 判定与数据库函数在同一组样例上结论一致（W6.2 批准后以集成测试固化，否则以预览输出比对）；W3.7 在非 UTC 会话下结论不变。
