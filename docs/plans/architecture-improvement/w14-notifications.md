# W14 通知与提醒

目标：玩家在 MoogleMail、论坛私信与网站上都能及时、准确地知道发生了什么、需要做什么、截止何时；运营者只在需要处理时被提醒。约束：已冻结的场次策略与投递载荷不改写；结果未知不重发；出价被超提醒保持不合并、不限额（决策 1）；通知正文只用英文（决策 59）；不新增 Public 页面显示（决策 65）；外发邮件消耗邮资与账号请求预算，新增通知一律经 W1.3 调度并定义失效条件。

| 项 | 内容 | 关键约束 |
| --- | --- | --- |
| W14.1 通知目录与模板 | 在[docs/guide/mail-flows.md](../../guide/mail-flows.md)建立通知目录：每种通知的触发事实、收件人、渠道、发送类别与出队位置、失效条件、模板键与冻结字段；出价被超（MM 与 PM）和论坛回执改由模板渲染（仍在创建时冻结正文），模板校验覆盖新键；新增占位符：lot 代码、装备名、世界与期号、有效截止、付款期限、网站链接（复用公开站点 origin 配置）、千分位金额 | 已冻结载荷原样发送，模板变化只影响新通知；正文不含代理上限与秘密（`register_key` 的登录 key 除外） |
| W14.2 内容修正 | 被超提醒写明 lot 代码、装备名、被超价格、当前有效截止与网站链接；COD 与载体付款邮件写明付款期限；卖方货款、载体与退款邮件写明 lot 与装备；寄回邮件区分流拍、撤拍与买家未付款后的退回；注册与换绑结果给出可读原因与下一步；慢速代理等待反击期间的提醒时机见 W14.11 | 只改新投递；Sent 精确证明继续以冻结正文摘要匹配 |
| W14.3 新增提醒（决策 64） | 启用投稿接收回执（lot 代码、场次、起拍价，按原邮件合并）、卖方成交与流拍汇总（每卖家每场一封）、换季前 isekai 领取与交付提醒；不新增付款期限前提醒邮件（期限已写入付款邮件，W14.2）与标记装备开拍或即将截止提醒。每项定义失效条件（已开拍、已过换季边界等即在 sending 围栏前退役） | 新提醒不改变冻结策略；换季提醒按冻结的赛季边界计算 |
| W14.4 论坛 notify 改为订阅（D10，决策 60） | `notify` 改为订阅该 lot 的被超提醒：在导入事务内为回帖者标记该 lot，按账号提醒渠道发送，不再寄导入回执；标记按用户 × lot 唯一，天然去重；每帖与每账号每场的订阅数设上限，超出写入系统日志楼；同步[docs/guide/forum.md](../../guide/forum.md) | 稳定命令 ID 不变；重放不重复标记，也不补寄旧回执 |
| W14.5 自动标记与渠道前置（D11，决策 60） | 网站普通出价在出价事务内自动标记（与新建代理一致），写入纳入 W12.3 负载演练；提醒偏好响应增加 PM 可用性（论坛同步已启用且已绑定论坛账号），不可用时拒绝保存并说明原因 | 偏好 DTO 变化按 W7.6 的契约演进规则；同步[docs/contracts/routes.md](../../contracts/routes.md) |
| W14.6 付款提醒联动（D9，决策 62） | 逾期提醒的领取要求付款投递已有发送证明（自动或人工），否则延后，并触发 W5.5 的“付款邮件未寄出但已逾期” | 不改已冻结的 `payment_deadline_at`，不新增恢复策略版本，不影响退件与恢复流程 |
| W14.7（取消） | 不新增 Public 显示：本人成交与付款、本人寄售、站内通知列表、公告横幅以及页内被超提示均不做（决策 65） | — |
| W14.8 通知指标与邮资 | 按通知种类统计创建、退役、抑制、发送、失败与送达延迟；`send_rejected` 细分出邮资不足；按发送次数与 W0.12 核实的邮资估算消耗，供 W11.2 使用；非结算通知投递失败接入 W5.5 | 标签为闭集，不含收件人或正文 |
| W14.9 收件人异常 | 零资产通知遇收件人不存在直接失败关闭并记审计，不进入人工对账；发送前核对收件人仍是该用户当前名称，改名后退役并记原因 | 带资产的投递维持现有退信人工流程 |
| W14.10 文档 | 玩家指南新增“会收到的邮件与提醒”；纠正[docs/guide/mail-flows.md](../../guide/mail-flows.md)中不存在的投稿接收回执；[docs/business-rules.md](../../business-rules.md)与玩家指南写明出价与新建代理自动标记、论坛 `notify` 为订阅被超提醒、PM 需绑定论坛账号，以及慢速代理等待反击期间不计入领先时长（会影响成交时的附加费或优惠）；每项玩家可见变化给出 Admin“规则内容”五语言更新稿 | 随所在工作项交付 |
| W14.11 慢速代理提醒时机（决策 67） | 持有人能够行动时才提醒：被超时若其代理仍在等待反击，只记录待定提醒、不入队；代理反超成功即作废；代理耗尽（到期无法反超、进入 Final 时无法反超，或等待期间被更高普通出价击败）时在同一事务入队；截止前仍未定的待定提醒按决策 14 退役；MoogleMail 与论坛 PM 同样适用 | 不改变竞价结果；提醒身份仍为 lot × 用户 × 领先周期，只改变入队时机 |

验收：通知目录覆盖全部出站种类，并与模板注册一致；新投递的被超提醒、付款与货款邮件不登录网站也能识别装备、金额与期限；论坛 `notify` 不再立即寄信，只建立有上限的订阅；网站普通出价后自动标记；选择 PM 而未绑定论坛账号时保存被拒并说明原因；付款邮件未寄出时不发逾期提醒且产生告警；W14.8 能分种类观察送达延迟与失败。回退：新正文可经 runtime 模板改回；新提醒、自动标记与订阅经 W7.7 运行时开关停用；通知事实只追加。
