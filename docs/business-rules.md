# 业务规则

[文档导航](docs/README.md) · [结算与履约](docs/guide/settlement.md) · [邮件流程](docs/guide/mail-flows.md) · [论坛](docs/guide/forum.md) · [玩家指南](docs/guide/player-guide.md)

本页汇总 HentaiVerse 装备拍卖的业务规则。规则的权威实现位于 [auction-domain](crates/auction-domain/README.md)（纯计算）与 [auction-application](crates/auction-application/README.md)（用例编排）；本页数值均为默认值，括号中给出对应配置项。

## 世界与场次

- 系统服务两个游戏世界：`main` 与 `isekai`。每个世界独立编号场次（期号），可在 Admin“参数配置”中即时启停。
- 每个场次在创建时**冻结**一份策略快照：经济规则、结算策略与恢复策略。之后修改配置只影响新场次，已有场次永远按冻结快照计算。

### 生命周期

```text
Draft ──► Preview ──► Live ──► Final ──► Settling ──► Settled
  │          │
  └──────────┴──► Cancelled（只允许开拍前取消，须记录原因与操作者）
```

| 状态 | 含义 |
| --- | --- |
| Draft | 草稿：接收邮件投稿的目标场次，目录对外不可见 |
| Preview | 预览：目录公开但不能出价；仍可继续接收投稿（每个世界同一时刻最多一个 Draft 或 Preview 场次接收投稿） |
| Live | 进行中：可以出价与设置代理 |
| Final | 最终阶段：仍可出价，但活动代理转为快速模式、不能新建 Slow 代理 |
| Settling / Settled | 结算中 / 已结算 |
| Cancelled | 已取消（只能在开拍前） |

### 周排期（`[auction.schedule]`）

启用后 Worker 按 IANA 时区（`timezone`）为每个参与世界（默认 main、isekai）维护每周一个场次：

| 阶段 | 默认时间 |
| --- | --- |
| 建立草稿 | 上一场开拍时同时建立下一场草稿（或 Worker bootstrap 补建） |
| 开放预览 | 周四 22:00（`preview_day`/`preview_time`） |
| 正式开拍 | 周五 00:00（`open_day`/`open_time`） |
| 计划结束 | 周六 12:00（`nominal_end_day`/`nominal_end_time`） |
| 进入 Final | 最早的 lot 有效截止前 15 分钟（`final_phase_lead_seconds`） |
| 结算 | Final 阶段中所有 lot 的有效截止都已过去 |

- 预览后、开拍前 2 小时起暂停该世界的收件轮询，开拍后恢复——开拍前的投稿进入本场，暂停期间到达的邮件在恢复后进入下一场。
- 每轮的本地时间来源（时区与三个本地钟点）在建立时冻结，夏令时按冻结规则换算，不从当前配置反推。

### 赛季早鸟期（`[auction.schedule.early_bird]`）

可选。赛季开始（默认每年 05-01 与 11-01 的 09:00）后的窗口（默认 7 天）内，用早鸟场次替代重叠的常规周场：

- 窗口内第 `session_days`（默认第 1、3、5、7 天）天的 `open_time`（默认 18:00）开拍，预览提前 `preview_lead_minutes`（默认 120 分钟，最少 120），竞价持续 `live_minutes`（默认 1440 分钟）。
- 默认只用于 isekai（赛季会清空异世界资产）。首场早鸟草稿建立后至赛季开始前暂停该世界收件（`pause_intake_before_season`），赛季开始后恢复，玩家可在首场预览前投稿。
- 窗口内的投稿可按 `qualities` 限定品质（默认不限）。
- 早鸟场次以 `early-bird:YYYY-MM-DD:N` 作为轮次身份。

### 手动操作

Admin 可在“拍卖场次”页对场次执行：进入预览、开拍（预览中且到达计划时间，或配置允许提前开拍）、进入 Final、提前结算（需配置允许）、取消（开拍前）、修改排期。Admin 与 Worker 使用同一套生命周期服务与排期日历，开拍时按日历建立下一场草稿。

## 投稿（寄售）

卖家把装备作为附件、以主题 `auction` 发 MoogleMail 给 Bot。系统读取装备详情并校验后接受，再收取附件；不合格时整封退回并说明原因。完整规则见[邮件流程](docs/guide/mail-flows.md#拍卖投稿)：

- 邮件只能包含装备附件；附带 Credits、COD 或其他物品整封退回。
- 装备必须可交易，品质达到门槛（默认 Legendary、Peerless），并通过可选的前后缀/分类/类型/等级过滤。
- 起拍价默认 50,000 Credits（邮件默认值，`[worker.mooglemail] start_price`），可在正文中用 `start <金额>` 统一指定或用 `<装备链接> start <金额>` 逐件指定，金额支持 `k`/`m` 后缀。
- 投稿进入该世界当前接收投稿的草稿或预览场次。

Admin 也可在后台手工录入装备（需要 `equipment_data_key`）。草稿状态的 lot 可以撤下或修改起拍价。

## 用户与登录

- 玩家以主题 `register` 发空邮件注册：系统以发件人游戏名建立账号，并回信发送 43 字符的**登录 key**。已注册玩家再次发送会重新获得 key（找回）。
- 改名后以主题 `rebind`、正文为旧 key 发邮件，把账号名称更新为新的发件人名称。
- 登录 key 只在回信中出现，服务端只保存摘要；Admin 可以重新签发或吊销 key。
- 登录时长由账号偏好决定：默认永久，可设固定期限；单账号并发会话数上限 5（`max_public_sessions`）。
- 在论坛回帖出价的玩家若没有对应账号（按已绑定的论坛账号 ID，或不区分大小写的同名账号匹配），系统会按论坛账号建立一个只能通过论坛参与、不能登录网站的账号；该玩家之后用同名游戏角色发 `register` 邮件即可取得登录 key。

### 黑名单

被拉黑的账号不能出价（`bidder_ineligible`）。拉黑由 Admin 执行，或在买家 COD 被退回达到上限时由恢复流程自动执行；黑名单在公开站点可查。

## 竞价

- **金额网格**：出价与代理上限必须是 1,000 Credits 的正整数倍，且不超过 1,000,000,000。
- **最低可出价**：无人出价时为起拍价；之后为当前价加增量。增量 = 当前价按 5%（`bid_increment_ppm`）计算后向上取整到 1,000 的倍数，至少 1,000（当前价先按千位向上折算）。
- **软截止**：每个 lot 有独立的有效截止时间。出价若在截止前 15 分钟内（`soft_close_window_seconds`）被接受，截止延长到“接受时刻 + 15 分钟”（`soft_close_extension_seconds`），只延后不提前。截止后的出价被拒绝。
- 已领先的玩家不能给自己加价；已有生效代理的玩家不能再普通出价。
- 每次被接受的出价都是只追加的事实，带接受后的截止时间与版本号；竞价日志公开可查。

## 代理竞价

代理授权包含上限与模式，系统在上限内自动为玩家反超：

| 模式 | 行为 |
| --- | --- |
| Fast | 被超越时立即以最低增量反超 |
| Slow | 被超越后等待 10 分钟（`proxy_slow_interval_seconds`）再反超；Final 阶段不能新建 |
| FinalFast | 进入 Final 阶段时，所有活动代理自动转为快速反超 |

- 他人出价超过代理上限时代理耗尽；恰好等于上限时代理以同价守住领先。
- 生效中的代理只能**降低**上限（不低于当前约束价），不能提高；被超越耗尽后可以重新设置，新上限必须高于上一份。
- 同一玩家在同一 lot 设置代理的次数上限默认 3（`proxy_max_outbid_uses`，0 为不限）。
- 本场可整体关闭代理（`proxy_enabled = false`）。
- 论坛回帖只支持普通出价，代理只能在网站设置。

## 装备标记与提醒

登录玩家可以标记关注的 lot，并在账号中选择提醒渠道：MoogleMail（`mm`）或论坛私信（`pm`），同一事件只走一个渠道。标记者在该 lot 上从领先变为被超越时，系统按所选渠道发送提醒——每个连续领先周期最多一次，自己加价不会开启新周期。论坛私信由独立队列发送，结果未知时只做人工对账，不重发。

## 结算

拍卖结算后，每个已售 lot 产生成交价、买方实付、卖方所得、税费与补偿，并生成需要履约的义务。规则摘要（详见[结算与履约](docs/guide/settlement.md)）：

- 卖方收到成交价全额（HoldCurveV2）。
- 买方根据**领先时长比例**调整：领先时间越短附加越多（最高 +8%），领先超过 25% 后转为优惠（最多 −2%）；附加费进入补偿池，优惠由补偿池按比例支付。
- main 世界：装备以 COD 寄给买方，买方收取时支付。isekai 世界：先在 main 发一封 1 Credit 的载体 COD 收款，确认付款后在 isekai 交付装备。
- 卖方货款在买方付款后支付；流拍与撤拍的装备寄回卖方。

## 付款超时与恢复

- 付款期限 7 天，期间提醒一次。
- 买方拒收导致 COD 被退回时：前 `cod_return_limit − 1` 次（默认前 2 次）重新寄出原 COD；第 `cod_return_limit` 次（默认第 3 次）把装备退回卖家并拉黑买家。
- 结果不确定的外部操作（例如邮件是否寄出）一律转为人工对账，由 Admin 在结算报表与投递队列中处理。

## 规则文档

玩家可见的规则文档（五种语言）由 Admin 在“规则内容”页编辑、校验、发布，也可用 `auction-cli rules import` 从目录导入。
