# 文档维护

[文档导航](README.md) · [协作规范](../AGENTS.md)

## 文档职责

| 位置 | 唯一职责 | 更新触发 |
| --- | --- | --- |
| 根 README | 产品、运行边界、最短阅读入口 | 产品范围或入口变化 |
| 根 DESIGN | 系统设计总览、核心数据流与边界；链接权威 owner，不另建契约清单 | 系统协作或设计边界变化 |
| 两个 Web crate 的 DESIGN | 分别拥有 Public/Admin 的信息架构、视觉与交互说明；不合并业务外壳 | 对应 surface 的页面、布局或交互变化 |
| docs/README | 全部正式文档的导航 | 新建、移动或删除文档 |
| docs/player-guide | 面向玩家的跨入口操作流程和能力限制；不替代已发布规则或所属 owner 契约 | 玩家入口、指令、金额、交互或履约方式变化 |
| architecture / tech-stack | owner、依赖方向、能力档位与技术取舍 | 跨模块或依赖策略变化 |
| contracts | 路由、事件、schema 与不变量 | 对外契约或持久化语义变化 |
| apps/*、crates/* README | 本模块职责、源码入口、关键限制与排错入口 | 本模块目录或实现变化 |
| ops、migrations、ci README | 操作前提、命令、结果和失败边界 | 配置、部署、迁移或门禁变化 |
| status | 实现/验证口径、源码缺口和未闭合事项 | 实现范围变化、发现契约偏差或新增可追溯运行证据 |

实现事实用源码、Cargo.lock、迁移和脚本核对；用户及 AGENTS.md 的规范约束不能因源码暂未实现就静默放宽。
发现二者不一致时，明确记下实现缺口。文档描述仓库固定版本，避免把快照写成长期有效的“最新 stable”。
命令中的数据库驱动、Web feature、角色配置、权限与破坏性确认必须与真实入口一致。

## 变更说明归属

每项事实由对应 owner 的文档完整说明，其他文档保留必要摘要和链接。模块 README 不复制完整路由、
配置字段、迁移或历史检查清单；版本只在技术栈说明集中列出。重要理由、备选、代价与限制直接写入
所属正式文档，不新增独立笔记目录、技能模板或平行记录：

- 系统边界和模块职责写入架构；技术选择与替代方案写入技术栈说明。
- Public、Admin 的界面设计分别写入各自 `DESIGN.md`；共享基础才进入共享模块说明。
- HTTP、事件、数据库与不变量变化同步对应契约，不能只修改总览或操作说明。
- 配置、部署、升级与恢复前提写入相关运维文档，敏感运行证据保存在受控目录。
- 源码能力、静态结果、历史验证与未闭合事项登记在 [状态说明](status.md)，不得把历史声明改写成当前验收。

已提交内容的历史由 Git 保留。当前设计变化应说明新理由与适用范围，不改写过去的验证日期、命令结果或证据边界。
局部排版、错别字和机械修改不新增记录文件。新增、移动或删除正式文档时同步 [文档导航](README.md)。

## 静态检查与人工核对

`just docs-check` 使用仓库 Rust 工具检查本地 Markdown 链接及标题锚点、从根 README 可达的文档覆盖、
Cargo 包 README。它不访问网络、不启动产品，也不执行行为测试。
脚本与检查限制见 [ci/README.md](../ci/README.md)。

人工审阅核对 CLI、字段 owner、能力范围和取舍；历史迁移、测试、锁图可选依赖及验证记录不能当作当前运行支持或验收证据。
格式检查不能证明这些语义。
