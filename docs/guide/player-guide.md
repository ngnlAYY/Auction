# 玩家使用指南（中文版）

[文档导航](docs/README.md) · [项目首页](README.md) · [功能与验证范围](docs/status.md)

面向购买、寄售装备及查看拍卖结果的玩家，说明官网、论坛和游戏内 MoogleMail 的配合用法；不含管理后台、
服务器配置或运维操作。正式使用前从运营者公告确认**官网地址、机器人游戏名、支持的世界、当期规则、排期和
联系渠道**，不要猜测收件人，也不要向陌生账号寄送装备；本指南不替代站点规则页。

## 快速开始

### 我想买装备

1. 阅读当期规则，确认装备世界、开拍时间、截止时间及付款方式。
2. 官网出价前，在游戏内向公告指定机器人发送标题为 `register` 的 MoogleMail 取得登录 Key。
3. 官网切换到“简体中文”，用完整 Key 登录，选择主世界或异世界。
4. 核对装备属性、当前价、下次最低价、领先者和剩余时间。
5. 使用“出价”或“代理”，检查确认面板中的实际 Credits 金额后提交，再核对服务器反馈和最新竞价记录；
   “已接受”不保证一直领先或最终中标。
6. 中标后核对结算邮件，通过指定 COD 邮件付款并领取装备；异世界付款与交付分两步。

也可使用论坛普通出价：帖子由系统异步处理，临近截止时不要以“帖子发出去了”断定“出价已接受”。

### 我想卖装备

1. 确认收件要求、机器人名称和投稿世界。
2. 在对应游戏世界发送标题为 `auction` 的 MoogleMail，附实际装备，不附 Credits、不设 COD。
3. 正文可不指定起拍价，也可用 `start` 指令。
4. 查看对应预览目录中的装备、卖家和起拍价；草稿期可能暂不可公开查询。
5. 成交后等待买家履约及结算付款；流拍装备由系统另行寄回原世界。

**注册、投稿、付款是不同流程**：`register` 不收装备，`auction` 不是付款指令，也不是充值。

## 世界、场次和装备编号

### 主世界与异世界

`Main` 是主世界，`Isekai` 是异世界；两个世界的装备目录、竞价对象和场次要分别核对，同名装备或相同编号不表示同一件
拍品。世界选择只展示站点已启用的世界，已关闭世界的已结算历史仍可能查询得到。当前结算流程中，**主世界和异世界拍卖的
付款、卖家收款及买家退款均使用主世界 Credits**，异世界装备仍在异世界交付。

### 论坛主题名称

```text
[Auction] Main Equipment Auction - Session 001
[Auction] Isekai Equipment Auction - Session 001
```

`Session` 后是场次期号，不足三位补零，标题不含日期；备注使用 UTC 格式
`Bid Start:开拍时间 UTC / Bid End:计划截止时间 UTC`，未排定截止时显示 `Bid End:Not scheduled`。备注是计划时间，
不是单件软截止延长后的实时截止。首帖顶部 `List Timer` 表示本场收件在开拍时关闭，`Auction Timer` 表示计划竞价截止。
倒计时由本站生成动态 SVG，到期显示 `Closed` / `Ended`，不依赖第三方服务；减少动态效果时看图片内 UTC 日期，
图片不可见时看首帖时间列表，改期后须刷新帖子。图片只展示计划时间，单件软截止仍以官网权威状态为准。

### 拍品编号

用 `One01`、`Two01` 等分类编号识别装备；各分类分别编号，必须保留完整前缀，不能只写 `01`。编号只在对应世界、对应
场次的目录中解释；发论坛指令时复制该主题目录页显示的完整编号，不要套用上一场、另一世界或旧主题编号。撤回后留下的
编号空缺不表示可以补占该号。

## 官网页面怎么用

以下路径相对于运营者公布的官网地址，不是管理后台入口。

| 页面 | 路径 | 玩家用途 |
| --- | --- | --- |
| 拍卖 | `/` | 切换世界、查看当前拍卖或预览目录、分类筛选、进入出价 |
| 往期拍卖 | `/auctions` | 按世界、状态和页码查找场次，打开拍品及出价记录 |
| 装备详情 | `/lots/{lot_id}` | 查看属性、游戏装备链接、价格、截止时间、竞价历史及本人代理 |
| 出价记录 | `/bidlog` | 按场次和拍品查看已入账的竞价事实及来源 |
| 历史成交价 | `/history` | 根据名称、世界、时间、价格、买卖方查询本站成交记录 |
| 论坛同步 | `/forum` | 打开对应论坛主题，查看同步开关和已处理楼层 |
| 我的出价 | `/me` | 登录后查看本人出价与代理授权 |
| 登录 | `/login` | 使用出价 Key 登录官网 |
| 规则 | `/rules` | 阅读本站已发布规则 |
| 黑名单 | `/blacklist` | 查看公开的禁拍名单和理由 |
| 补偿池 | `/compensation-pool` | 查看共同资金池余额、场次和流水 |
| 服务状态 | `/status` | 阅读服务说明；不是付款完成或全系统健康的实时证明 |

装备详情从目录中的“查看”进入，不需手工拼接 `lot_id`；长名称被截断时用全文提示或展开查看，“在游戏中查看装备”
用于核对游戏内详情，站点未提供有效游戏链接时不要自行补造 URL。

目录、往期拍卖、出价记录、装备竞价历史、成交价、黑名单及补偿池默认每页 10 条，可选 10/20/50/100，也可输入正整数
后点击“应用”（不再限制 200 条）；0、负数、小数及超出系统整数范围的值不会提交或保存，数量越大读取和渲染成本越高。
选择保存在当前浏览器并在下次进入时恢复，链接明确指定数量时优先，不覆盖已保存偏好；改变数量返回第 1 页且保留筛选，
支持数字页码与输入跳转，刷新与前进/后退会恢复选择；补偿池流水有独立分页和数量偏好，切换批次页会收起流水。
未登录可浏览公开目录和历史；官网出价、代理、装备标记及本人记录需要登录；切换界面语言不等于站点已发布该语言规则。

## 注册、登录、找回与改名

### 首次注册

在运营者指定、系统支持的游戏世界，通过 MoogleMail 给机器人发信：

```text
标题：register　正文：可留空　装备附件：无　Credits：0　COD：0
```

标题只写 `register`，不附加姓名、说明或首尾空格；系统按实际发件人识别，不靠正文自报姓名。处理成功后机器人回复
登录 Key（默认回信标题 `Auction login key`），取得回信后打开官网“登录”，只复制完整 Key（不含整段说明），
点击“登录”并核对页头玩家名，再回到目标世界、场次及拍品操作。

当前邮件签发的 Key 是 **43 个字符**、区分大小写；界面提示的“32 位 Key”是文案偏差，**不要据此截断 Key**。
Key 是官网登录凭据，不是论坛密码、游戏密码或 Cookie。注册没有即时完成时先检查收件人、标题和机器人处理状态，
不要连续寄送多封同样邮件；带装备、Credits 或 COD 的注册邮件会进入拒收处理，不会作为注册费用。

### 找回 Key

从已登记的游戏身份重发无资产的 `register` 邮件；系统可恢复已有 Key，或在需要时重签，以回信为准，不要假设每次注册
都会新建账户或更换 Key。重签后旧 Key 及原有官网会话失效，需重新登录；黑名单和身份冲突不会因重复注册自动解除。
无法从原身份找回、已改名或收到冲突结果时联系运营者核对，勿把旧账户当成已合并或迁移成功。

### 游戏改名后的换绑

保留原有效 Key，并用**新的游戏名称实际发信**给机器人，正文只粘贴原有效 Key，不附装备、`Credits: 0`、`COD: 0`，
不放多个 Key：

```text
标题：rebind　正文：只粘贴原有效 Key　装备附件：无　Credits：0　COD：0
```

系统按实际发件人绑定新名称，不按正文写的新名字操作。收到成功回信后重新登录并检查名称及原有记录，此操作不会发放
另一把 Key。Key 无效或已撤销、账号在黑名单中、目标名称已有其他账户时可能被拒绝；当前换绑只接受系统邮件格式的 Key，
旧版手工 Key 需运营者处理。有尚未完成的付款、发货或卖家收款时，改名前先联系运营者，不能假设已发出的邮件和冻结
收件人会自动改名。

### 退出登录

公共设备用完后点击页头“退出登录”并确认成功；退出报错时不能认为会话已撤销。登录失效后需重新登录，不要把未确认的
出价结果当作因退出或过期而自动取消。

## 拍卖阶段与截止时间

| 页面状态 | 玩家应做什么 |
| --- | --- |
| 即将开拍／草稿 | 等待目录及排期，不把收件完成当作已经开拍 |
| 预览 | 浏览装备和起拍价；目录仍可能增加装备，不能正式竞价 |
| 开拍处理中 | 等待状态更新，不把倒计时归零当作已经开放出价 |
| 进行中 | 按资格、金额和拍品截止时间出价或使用代理 |
| 最终阶段 | 仍需核对拍品是否接受出价；不能新建慢速代理 |
| 落锤中／已结束 | 不再依赖本地倒计时提交，等待权威状态和结算 |
| 结算中 | 等待价格与履约责任确定，不等于付款或发货已经完成 |
| 已结算 | 查看结果、结算邮件和历史；装备交付、卖家收款仍可能处理中 |
| 已取消 | 不再参与该场，联系运营者确认涉及装备的返还 |

开拍时间、计划截止时间与**单件拍品的有效截止时间**要分开看：浏览器倒计时只是展示，服务器决定是否接受命令；论坛
处理存在延迟，帖子发表时间不是竞价已被接受的证明。当前默认规则在计划截止前 15 分钟进入最终阶段，每场使用自己的
冻结规则，以实际状态为准。

### 软截止延长

未来新场次在单件拍品截止前最后 15 分钟接受有效出价时，把截止延到“接受时间之后 15 分钟”，且只允许向后延长：
原截止 `12:00:00`、在 `11:47:00` 接受出价时，候选新截止为 `12:02:00`，不是一律在旧截止上加 15 分钟。每次有效出价
均使用固定 15 分钟规则，不采用分段 15/5/1 分钟；已发布场次仍按其冻结策略执行，不追溯或自动重开。后续出价可能继续
延长，以拍品实时有效截止时间为准，不以论坛备注或旧截图判断已经落锤。不要卡最后一秒提交：网络、身份检查、论坛扫描
和系统处理都可能使请求赶不上截止。

## 卖家投稿与起拍价

### 正确投稿方式

在装备所在且本站支持收件的游戏世界发信：

```text
标题：auction　正文：留空或使用起拍价指令　装备附件：附上要寄售的实际装备　Credits：0　COD：0
```

- 只发装备链接不能代替装备附件；本文不提供材料或其他非装备资产的投稿方式。
- 不附 Credits、不设 COD；这些资产组合会被拒收，不会作为保证金或手续费扣收。
- 装备还须通过本站分类、属性及其他收件筛选，能寄出不代表一定可以上架。
- 一封多装备邮件中，定价、装备读取或筛选出问题时可能整封拒收，不要假设其余装备已单独入库。
- 拒收或退件时核对原邮件和实际装备状态，再决定是否重投，避免把结果未知当作资产已退回。

### 起拍价与定价指令

不写 `start` 定价指令时使用本站录入默认起拍价；仓库默认 `1,000 Credits`，站点可另行配置，以预览目录中实际显示的
起拍价为准。正文只写 `start 50k` 表示本封全部装备均使用 `50,000 Credits` 起拍。按装备分别定价时用“完整装备链接 +
start + 金额”，一件一行：

```text
装备A的完整链接 start 50k
装备B的完整链接 start 1.5m
```

“装备A的完整链接”等是说明占位，发送前必须换成游戏提供的真实完整 URL；链接中的装备 ID 和 Key 必须与本封附件对应。
逐件链接定价中未指定的附件使用默认起拍价；同一件装备不要重复定价，不要引用未附在邮件中的装备；不要混用整封
`start 金额` 与逐件链接定价。推荐正文只保留定价指令，需备注时使用单独以 `#` 开头的注释行，避免说明被误识别。

起拍价支持正整数 Credits 及能精确换算为整数 Credits 的 `K/M` 缩写，不支持 `B` 后缀；起拍价解析与普通出价的整千
网格不是同一规则，为便于后续出价建议选用整数 K 的起拍价。

### 收件后在哪一场出现

投稿进入该世界当前可录入的草稿或预览场次；**预览目录并未冻结**，此时合格投稿仍可加入这一场。正常开拍并切换收件
目标后，新投稿进入后继草稿，不会追加到已开放竞价的当前场。不要按邮件发送日期或自己的估计指定期号，以实际目录或
运营者确认为准。当前接受流程主要入库及领取附件，不保证发送独立的“投稿成功”通知信；未收到成功回信不能单独证明
失败，草稿期目录不可见也不能单独证明装备丢失。

## 官网普通出价

### 操作步骤

1. 登录，核对账户名和世界。
2. 在拍品目录或详情点击“出价”。
3. 检查当前价、下次最低价和截止时间。
4. 在“出价金额（单位：K）”输入不带后缀的整数。
5. 查看确认面板中的实际金额和拍品编号，再点“确认出价”。
6. 等待服务器结果，然后核对当前领先者及竞价历史。

**输入 `200` 表示 `200,000 Credits`，不是 200 Credits**；此输入框不要写 `200k`、`0.2m` 或带逗号的数字。普通出价须为
`1,000 Credits` 的整数倍，新出价最高 `1B = 1,000,000,000 Credits`（即此框的 `1000000`），该限制不表示含税结算款或
多件合计金额也只能到 1B。默认普通加价为当前价的 5%，增量向上按整千计算、至少加 `1,000 Credits`，场次可使用其他
冻结规则；首次无领先者时可从起拍价出价，始终以页面“下次最低价”为门槛，不靠旧截图自行计算。最低价不是整千时，
外部输入仍需整千并达到该门槛，不能向下取整后提交。

### 已接受、领先和中标不是同一件事

服务器可以接受你的出价，但其他玩家的代理可能立即参与竞争，需查看最终反馈及刷新后的领先者。已经领先、资格不足、
拍品未开放、金额不足或已达上限时，页面可能禁止新出价。出价不是立即扣款或领装备，最终中标后才进入结算和 COD 履约。
**没有玩家自助撤回已接受出价的入口**；弹窗的“取消”“返回修改”不撤销服务器已经接受的命令。

### 网络超时或结果未知

优先使用页面提供的原请求重试：它沿用同一拍品、金额及命令身份，用于恢复原结果，不是新的加价。未确认前不要改价反复
提交、重建代理，也不要以为刷新后出现新最低价就证明原请求失败。已关闭弹窗、换了拍品或退出账户时，先查本人出价和
拍品历史，再决定是否提出新意图。取消表单或关闭页面不会取消可能已被接受的出价；读取失败可重新读取，写入结果未知
须先核对原结果再重发。

## 官网代理出价

代理让系统在规则允许的范围内代你竞争。**上限不是保证成交价，也不是预先扣款金额**；公开目录和普通竞价日志不展示
本人秘密上限，登录后的代理页面可以查看它。

### 创建代理

1. 点击对应拍品的“代理”。
2. 输入上限，选择可用模式，查看配额及可执行能力。
3. 确认实际金额、模式和拍品，再点“确认创建代理”。
4. 查看服务器结果与本人授权状态，不仅看按钮是否点击成功。

上限支持 `K/M/B`，例如 `100K`、`1.005M`、`1B`；必须精确落在 `1K` 网格上且不超过 1B。`M` 最多三位小数、`B` 最多
六位小数，不能提交后由系统自动取整；低于页面所示下限也会被拒绝。

### 模式与上限调整

| 模式 | 行为 | 玩家注意 |
| --- | --- | --- |
| 快速（Fast） | 上限立即参与竞争，产生的公开价格变化立即发布 | 可能立即改变当前价；同价时按既有代理优先规则处理，不是后提交必定获胜 |
| 慢速（Slow） | 首次代理价立即生效；之后符合慢速竞争条件时，等待再释放出价 | 不是每次立即反超；页面“等待”不表示授权损坏或已经结束 |

当前默认慢速间隔为 10 分钟，实际使用本场冻结规则；进入最终阶段后既有慢速代理自动转为快速，最终阶段不能新建慢速
代理。代理可能因竞争、使用次数、阶段或资格变化进入耗尽、冻结或关闭状态；默认反超使用次数上限为 3，场次可另行设置
或不受限，以页面次数、状态和可执行能力为准，代理不是可无限次重新录入的授权。

已有本人有效授权时使用“降低代理上限”：新上限必须严格低于原上限，仍须满足当前绑定价格等限制，不能靠降额撤销已
发生的竞价责任。页面显示“不能降低”时不表示网络重试能绕过限制；当前没有自助任意加额或直接删除有效代理的操作，
不要以创建第二份授权代替修改。后续重新录入须满足服务端条件，包括新上限严格高于前一授权上限及次数限制，不保证一定
可重新创建。同样遵守结果未知时重试原请求的规则；切换拍品或账户不会自动撤销原授权。

## 论坛出价与处理结果

### 使用正确主题和楼层

从官网“论坛同步”打开对应世界、当前场次的主题，不要仅靠搜索到的相似标题出价。帖子已同步时，点击状态提示行右侧的
“查看论坛帖子”；公开页保留同步进度，不再内嵌帖子正文。

- **目录页**：从 #1 连续排列，每帖最多 150 件；#1 另含说明，各页显示对应装备及公开当前价。
- **更新楼**：紧接最后一个目录页，显示系统处理进度、拒绝、待重试或忽略摘要。
- **玩家回帖**：从更新楼的下一楼开始，不在目录或更新楼放竞价。

150 件使用 #1 目录、#2 更新、#3 起竞价；151–300 件使用 #1/#2 目录、#3 更新、#4 起竞价；301–450 件使用
#1/#2/#3 目录、#4 更新、#5 起竞价，以此类推，以主题楼层说明为准。升级前已开始发布的旧主题仍保留 #1 目录、
#2 更新、#3 起竞价，不会为分页挪动既有出价帖。

论坛竞价使用论坛自身的登录身份，系统核验帖子作者及其与玩家身份的关联，不要在正文自报另一个账户或公开官网 Key。
首次论坛竞价可以建立仅用于论坛的身份记录，但不自动取得官网登录 Key，官网登录仍需邮件注册；身份无法关联或冲突时，
按更新楼提示联系运营者。

### 普通出价语法

每行一条指令：

```text
One01 200k
Two01 1.5m
```

也可在同一行对多个拍品提出相同金额：`One01 Two01 200k`。多拍品逐件处理，不是全部成功或全部失败的打包交易，必须
分别核对结果；示例只说明语法，不保证编号存在、金额足够或提交时仍能竞价。论坛金额支持 `K/M` 或原始整数 Credits，
不支持 `B` 后缀，普通出价仍须整千且不超过 1B；裸数字 `200` 表示 200 Credits（不是官网输入框里的 200K），会因不满足
金额网格被拒绝。命令行不要附加解释、感谢或其他词，需要聊天时使用另外的非指令内容，并预期它可能被标记为非命令；
`start`、`cancel` 属管理操作，不会替玩家开拍、撤拍或撤回出价。编辑过的帖子不会产生新的竞价命令，也不能撤回已入账
事实：需要新的更高出价时先核对当前结果，再新增未编辑的回帖，每个新帖都是新操作，不是自动重放原帖。论坛里的
`proxy` 行会被忽略，不会创建或降低代理，且不保证在更新楼单独提示；所有代理创建和降额都应在官网操作。

### 怎样判断论坛出价是否成功

1. 在更新楼和官网“论坛同步”检查处理进度是否已覆盖自己的楼层。
2. 查看该楼层是否有身份、金额、状态或待重试错误。
3. 到官网竞价记录核对该拍品的持久化出价事实及领先者。

“当前同步到 #N”只表示已处理的连续楼层，**其中可以包含拒绝、忽略或非竞价内容，不表示这些楼层全部出价成功**；
正常成功不一定逐条显示在更新楼，最终应结合官网记录判断。更新楼使用英文原因说明，并链接原帖及标注行号：

- `already_leading`：出价者已经领先，不能再次用普通出价抬高自己的价格；新金额不会改变现有出价或代理额度。
- `bid_too_low`：金额低于所需最低价，先在官网核对当前价和最低加价。
- `invalid_amount`：金额不符合格式、信用网格或范围要求。
- `auction_closed`：系统处理时已过有效截止时间，该出价未被接受。
- `bidder_ineligible`：当前身份不具备竞价资格，需联系运营者。
- `command_rejected`：没有可安全公开的具体分类，提供主题、楼层和拍品编号供运营者核对。

新版可从已知旧拒绝记录补充展示原因，不会重新执行旧出价；格式错误应在核对结果后新增更正回帖，身份或幂等冲突先联系
运营者。更新楼分开统计 pending、警告及忽略，最多显示 100 条并受帖子字节上限约束，优先待重试和近期错误，有省略时
标出已显示/总条数；省略不代表问题已解决，仍以官网事实和连续处理水位判断。通知失败或待重试不等于出价失败，不要为
重试通知重复提交出价；论坛暂时失败或待重试时系统可能停在前一楼层，未确认前不要连续补发同一操作。临近截止建议使用
官网并及时确认结果，发帖成功不是系统赶在截止前接受出价的保证。

## 通知的使用与限制

### 官网标记与超价提醒

登录后可在装备目录或详情标记装备。标记按账号保存到服务器，当前浏览器另存同账号、同场次缓存；换设备登录后以服务器
为准，不合并另一账号或过期本地记录。页面未完成同步时不能修改，保存成功后才视为服务器已接受。

- 普通出价不会自动标记；新建代理成功时默认标记，升级会给已有有效代理补建标记，但不补发历史提醒。
- 手动取消后，刷新、降低代理上限或自动追价不会重新标记；之后新建一份代理授权时会再次默认标记。
- 已标记装备从**你领先 → 被别人超越**时按账号渠道发送一次警告；其他人继续加价不重复提醒，你重新领先、再被超越时
  可再次收到一封。仅收藏未出价、标记时已经落后的装备不会立即收到邮件，浏览器关闭不影响后续服务器提醒。
- 取消标记停止后续提醒；取消或重新领先会使尚未开始发送的旧提醒失效，已进入发送或已收到的邮件无法撤回。
- 在“我的账户 → 竞价警告”选择 MoogleMail（MM，默认）或论坛私信 PM 并保存；这是账号级设置，不同时双发。
- 渠道仅影响后续反超事件，已排队通知仍按原渠道处理，不撤回、不补发；不影响结算/COD，正文不含代理秘密上限。
- 偏好跨设备同步，权威状态加载完成前不可保存；未知请求保留原命令重试，冲突时先明确刷新。

网络超时或结果未知时使用页面保留的原请求重试，不反复切换标记；普通翻页不会丢失待定请求，离开该场页面、换号或刷新
整页后不会自动补交，重新进入先读取服务器状态；版本冲突时先刷新核对。MM 仍依赖运营者启用并正确配置邮件服务、有效
凭据和发送预算；PM 依赖启用论坛服务、稳定论坛账号身份及原发件账号凭据。缺少稳定论坛身份的 PM 不会改发 MM，保存
偏好不等于可送达；两种方式都可能延迟或需人工核对，通知失败不撤销已接受竞价，已标记不代表已寄出，价格以官网为准。

### 论坛单次通知

可在未编辑的论坛回帖中请求 MoogleMail 通知：`One01 notify mm`，也可随普通出价一起 `One01 200k notify mm`。

- `notify mm` 请求的是**单次普通论坛拍卖通知邮件**，不是持续反超订阅，也不是实时竞价成功回执；配合出价时，出价成功
  后再请求通知，通知失败不撤销已经接受的竞价。
- 默认通知标题为 `Forum auction notification`，当前默认正文不提供拍品实时价格或完整出价结果。
- 论坛 PM 未接入：`notify pm` 不会产生可用 PM，不指定模式的 `notify` 也不能保证 PM，应明确写 `notify mm`。
- 邮件能力未启用或暂不可用时，通知可能无法入队或延迟；以更新楼、实际邮件及官网记录分别核对。

论坛 `notify` 与官网标记是两种独立能力，不会互相开启或取消。**需要超价提醒时使用官网标记**，并自行关注拍品和本人
代理状态，不把通知当作到信保证。

## 落锤、付款与装备交付

### 成交价为什么不一定等于应付金额

出价金额、落锤成交价、买家应付、卖家应收是不同字段：当前结算可依据最终领先时长计算税、折扣及补偿，历史场次也可能
使用零调整策略；每场创建时冻结策略，不用当前默认规则重算过去场次。“领先时长比例”是最终赢家在该场拍卖期间**累计领先时长**
（多次领先区间相加，不要求最后一次连续到结束）相对于计划竞价窗口的比例（最高按 100%），不是账号年龄、装备持有天数或等待付款时间。

论坛结算后沿用赢家、落锤价及真实来源，追加 `; winning for Xh / Yh; adjustment%`：X 是最终赢家在该场拍卖期间的累计领先时长
（各段领先区间相加，包含更早失去后又重新取得的周期），Y 是计划截止减计划开拍（不是实际开拍时间或当前时间），小时
四舍五入到一位小数；累计时长可大于 Y，结算比例仍按既有规则封顶 100%。调整来自当场持久结算：每 10,000 PPM 为 1%，最多
四位小数、去尾零，负号为折扣、正号为税、零为 `0%`；它不是买家最终净支付比例，不包含补偿池额外抵扣。论坛来源保留
真实 #楼层及原帖链接，官网/代理来源不伪造楼层，流拍不显示赢家时长或调整；只更新升级时尚未结算及之后创建的拍卖，
升级前已结拍主题不回填，未取得权威结算不会拼造最终数字。

默认曲线参考如下，场次可采用另一份已冻结曲线：

| 领先时长比例 | 默认调整 |
| --- | --- |
| 0% | 买家加收 8% |
| 5% | 买家加收 6.4% |
| 10% | 买家加收 4.8% |
| 15% | 买家加收 3.2% |
| 20% | 买家加收 1.6% |
| 25% | 不调整 |
| 30% | 折扣 0.4% |
| 40% | 折扣 1.2% |
| 50%–100% | 折扣 2% |

中间比例使用整数规则插值，实际金额由系统计算，不按表中百分比自行转账。正调整时税由买家额外承担，卖家应收保持成交价，
税收入补偿池；负调整时先按成交价计算折扣，卖家应收相应减少，有可用补偿池时买家还可得到额外抵扣。补偿依本场总折扣
需求和可用余额分配，每件补偿不超过其折扣，不保证每次都足额，也不是玩家可在网页额外点击“领取”的红包。

例：落锤价 100K、调整 +8% 时买家应付 108K、卖家应收 100K；调整 −2% 时卖家应收 98K，买家补偿前应付 98K，获得足额
2K 补偿则应付 96K。示例不是当前拍品的付款指示，正式付款以可核对的机器人结算邮件为准。

### 主世界装备

```text
拍卖结算 → 主世界收到装备 COD 邮件 → 核对并领取附件、支付 COD → 系统确认付款与交付
```

检查发件人确为公告中的机器人，核对装备身份、邮件说明、关联编号和 COD，确保主世界有足够 Credits 后通过该 COD 邮件
领取装备并付款；保存邮件证据并等待系统确认，不另寄一封纯 Credits 邮件重复付款。

### 异世界装备

```text
拍卖结算 → 主世界收到付款 COD 载体 → 支付并领取载体 → 系统确认付款 → 异世界发送装备
```

主世界付款邮件带 **1 Credit** 作为载体，不带所拍异世界装备；邮件 COD 是“拍卖应付金额 + 1 Credit”，同时取得载体的
1 Credit 后净支出仍为拍卖应付金额，不要误把多出的 1 Credit 当作错误后拒绝领取。系统确认主世界付款后才在异世界发送
装备交接邮件，交接不再收 COD；不要改用异世界 Credits 付款，也不要另发现金替代指定的主世界 COD 流程。已付款但未收到
装备时，先区分“已领取付款载体”和“异世界装备已交付”，长期不明时把原付款邮件和场次信息交给运营者核对，勿重复付款。

## 卖家收款、流拍、撤拍与退款

### 成交后的卖家收款

卖家款项由机器人以**主世界 Credits** 发送，取决于买家付款及装备履约条件完成，不是网页出现“已结算”就立即到账。核对
收款金额与关联拍品，不把落锤价直接当作必然净收入（有折扣时卖家应收会变化）；同场多件应逐件核对，不能用一笔到账
推断全部已结清。

### 流拍与撤拍返还

流拍或经管理流程撤回的装备，按原装备、原卖家和原游戏世界另行寄送返还，返还邮件 Credits 和 COD 均为零，玩家应核对
实际装备后领取。原投稿邮件可能早已被机器人领取，不能期待系统靠退回整封原邮件找回某一件装备；多附件投稿中的单件
撤回，不表示同封所有装备都被撤回或整封退回。

玩家没有官网自助撤拍入口，论坛 `cancel` 也不能撤拍。需要撤回时应尽早联系运营者，由其核对拍卖阶段、拍品状态和返还
责任；不能保证任何时刻都能撤回。

### 逾期、拒收与退款

当前恢复策略使用 7 天付款观察期限和最多一次提醒；不要理解为“从第一次打开邮件起一定还有 7 天”，也不要等待提醒才
检查付款，具体期限和责任向运营者核对。未付款、退回结算邮件、装备交付失败或外部结果无法确认时，可能进入核对、重新
挂拍、退款或资格处理流程；不要把直接退信当作已获准取消交易，也不要假设逾期会自动退款且无违约后果。当前没有网页一键
退款或“我已付款”按钮：已付款但无法交付等恢复处理由运营者核对付款与装备证据后处理；符合条件的买家退款以主世界
Credits 发放，不修改或删除过去的出价记录，金额及是否成立以该笔恢复结果为准。

## 查记录、估价与补偿池

### 我的出价

在 `/me` 查看本人出价和代理授权；代理上限、模式、次数、状态及授权变更只按本人权限读取。历史出价说明曾经提交了什么，
不保证现在仍领先；当前是否领先、是否耗尽、能否降额应结合拍品及授权当前状态判断，代理页面显示“等待”时先看模式和
下次执行条件，不要立即重建同一授权。

### 公开竞价记录

在 `/bidlog` 选择世界和场次，可按完整拍品编号或详情对应拍品筛选：论坛来源有可核对的真实楼层时显示楼层标记或链接；
代理来源标为代理，不公开秘密上限，也不靠这条公开标记区分快速与慢速；普通官网出价没有论坛楼层；旧论坛记录缺少楼层时，
不应自行根据其他 ID 猜测帖子位置。

### 历史成交价

在 `/history` 用装备名称、世界、时间、价格和买卖方筛选，必要时放宽或清空筛选；界面价格筛选的 K 用整数、M 最多两位
小数，与代理金额输入精度不同。统计只覆盖本站已结算且符合筛选条件的记录，不是全游戏市场报价，不保证相似装备再次同价
成交；历史价格也不是付款、交付或卖家收款完成的凭证。

### 补偿池

`/compensation-pool` 显示两个世界共用的主世界 Credits 资金池，展开某场可查看税收、补偿支出及拍品流水。基本核对关系是
`期初余额 + 税收收入 = 补偿支出 + 期末余额`。补偿参与结算抵扣，不需要玩家再发送领取指令，也不是本站可以任意提取的
账户余额。

| 提交成功但不领先 | 其他玩家或代理已参与竞争，检查最新价格与领先者 |
| 当前价变了，旧请求却显示未知 | 优先恢复原请求结果，不能用新价格重拼旧请求 |
| 论坛回帖发出但官网无记录 | 检查更新楼和已处理楼层；发帖不等于接受，临近截止尤其有风险 |
| 编辑旧帖后金额没变 | 编辑帖不会产生新命令，已接受出价也不会撤销 |
| `proxy` 回帖没有报错也没效果 | 论坛代理会被忽略，改用官网代理入口 |
| `notify` 没有持续反超提醒 | 论坛指令只请求单次普通通知；超价提醒需登录官网标记装备 |
| 标记了却没收到超价邮件 | 仅你领先后被超越才触发；已落后时标记不补发，未发送提醒会在取消/重新领先时失效，另需核对邮件服务 |
| 已结算但没有收到装备或卖家款 | 结算与外部履约是不同步骤，核对 COD 付款、世界及邮件证据 |
| 异世界买到了装备却只收到 1 Credit | 这是主世界付款载体；付清并经系统确认后，装备在异世界交付 |
| 显示需手动刷新／实时连接异常 | 点击“立即刷新”，核对最新快照后再操作，不把旧显示当权威状态 |
| 论坛显示关闭 | 当前不会按启用流程持续扫描新论坛命令，不应依赖论坛出价 |
| 论坛状态不可用 | 不等于开关已关闭；先重试读取并联系运营者，不据此猜测帖子是否被处理 |
| 规则暂不可用 | 联系运营者确认已发布规则，不拿本指南或默认参数冒充本站规则 |
| 账户在黑名单中 | 查看公开理由并联系运营者；重复注册或换 Key 不能自动解除禁拍 |
| 功能显示不支持 | 当前部署未装配所需能力；联系管理员核对，反复重试不能补齐 |

连接状态良好不代表每笔命令成功，连接状态异常也不撤销已接受的命令；显示“服务状态”或某一张表为空，不能证明全部后台
正常、自己没有待付款义务或资产已经返还。

## 安全与联系运营者

### 安全检查

- 只使用运营者公布的官网和机器人；支持 HTTPS 时优先使用经过确认的 HTTPS 地址，警惕相似域名。
- Key 具有登录及出价授权用途，不应公开；不要把 Key、论坛 Cookie、会话信息或完整注册回信放进帖子、截图或公开聊天。
- `rebind` 的 Key 只发给已确认的机器人，不发给自称客服的陌生账号。
- 确认金额单位、世界、场次、完整编号和 COD 后再操作；不要用历史示例价格作为当前付款指示。
- 公共设备退出后确认结果；Key 疑似泄露时立即联系运营者撤销或重签，不靠修改论坛帖子消除风险。
- 遇到结果未知、重复付款、装备已移交但页面不明时，保留现场证据，不反复寄送资产尝试“修好”。

### 提供哪些信息

通过运营者的正式联系渠道提供：玩家名、涉及世界、场次期号、完整拍品编号和官网拍品链接；所执行的操作及时间（注明时区）；
可公开的错误提示、关联编号或请求 ID（页面有显示时）；论坛问题附主题链接、楼层和帖子链接并说明是否被编辑；邮件问题附
发件人、收件人、邮件 ID、标题、装备身份、Credits、COD 和当前领取／退回状态；涉及付款、发货或退款时说明哪一步已经完成。
提供截图前隐藏登录 Key、会话凭据及其他敏感信息。
