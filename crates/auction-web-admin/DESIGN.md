# Admin 管理端设计

[系统设计](docs/design/architecture.md) · [模块说明](crates/auction-web-admin/README.md) · [文档导航](docs/README.md) · [独立的 Public 设计](crates/auction-web-public/DESIGN.md)

本页描述现有 Admin 界面设计与交互约定；操作授权与运行证据另行确认，源码和线上制品边界见[状态页](docs/status.md)。

## 1. 定位与隔离

管理端服务可信操作员，目标是清楚区分当前事实、候选修改、已接受命令和外部最终结果；界面优先保证可审查、可追踪、
可恢复，不把危险动作包装为普通快捷按钮。管理页面及认证内状态由 [src/app/](crates/auction-web-admin/src/app/) 拥有，API/命令提交由
[src/api/](crates/auction-web-admin/src/api/) 拥有；专属样式为 [admin.css](crates/auction-web-admin/assets/admin.css)，
文案为 [i18n/](crates/auction-web-admin/i18n/)。Admin 不导入 Public，`/rules` 别名转到独立的校验/发布页，
共享层不拥有权限、配置草稿或业务命令。

## 2. 信息架构

| 页面族 | 入口示例 | 操作员关注点 |
| --- | --- | --- |
| 总览 | `/` | 单份安全快照、进程与 Worker、邮件轮询、凭据可用性及任务水位 |
| 拍卖、结算与恢复 | `/auctions`、`/settlement` | 创建、计划时间、生命周期、手工录入、撤拍及 settled 报告事实 |
| 邮件与投递 | `/mails`、`/deliveries` | 收件诊断、关联任务、轮询、重试及人工对账 |
| 用户与凭据 | `/users`、`/renames`、`/cookies` | 账号投影、登录 Key、论坛身份、黑名单、改名历史与 Cookie 只读校验 |
| 规则与运行配置 | `/rules-content`、`/config` | 语言/版本/草稿/校验/发布；候选配置、指纹、差异与重启要求 |
| 实时与审计 | `/outbox`、`/audit` | 安全事件元数据、lag/failure、受控 replay 及追加式审计读取 |

上表使用正式入口；兼容别名与导航顺序以源码为准，完整登记见[HTTP 契约](docs/contracts/routes.md)和
[入口清单](crates/auction-http/src/assets/routes.rs)，保留入口不因存在路由就进入主导航。

## 3. 外壳、认证与布局

正式页面先通过 Admin 会话外壳，未认证的深链接或未知路由不能绕过会话加载与错误处理；业务写入携带所需 CSRF，
浏览器不自行判断权限或数据库资格，只有权威会话结果确认未认证才回登录页。
后台会话复核的临时错误不卸载已经确认的认证子树，草稿、一次性结果及未知命令继续保留；
原生控件与 API-owned 写门禁同时禁写，CSRF 获取前后均复核许可。明确 401/退出清理旧树，
账号或 CSRF 身份变化建立新的身份代数，迟到旧响应不能恢复旧授权。

```text
管理端标识                                  语言 / 操作员 / 退出
─────────────────────────────────────────────────────────────
扁平导航  │ 页面标题 / 主要操作 → 筛选或状态摘要 → 列表、表单或报表 → 分页 / 命令反馈
```

`admin-shell` 桌面侧栏宽度为现有 `12rem`，活动入口使用强调色背景与可访问的当前页标记；窄屏改为顶部折叠菜单，
不套用 Public 页头和世界切换器。主区保留 `min-inline-size: 0` 与受控内边距，操作栏和筛选可换行而不横向滚动；
登录页采用最大 `22rem` 的窄表单。Dashboard 按业务分组响应式分栏，结算页始终“轮次选择在上、报告在下”，
危险动作和异步任务结果必须能追溯到对应实体。

折叠菜单覆盖 48rem 内的窄屏，以及 64rem 内的触控横屏。两列导航沿文档流展开，保留原生链接和
`aria-expanded/aria-controls`；点击入口、浏览器前进/后退及站内路由变化均收起，导航内 Escape 收起并恢复菜单按钮焦点。
页面保留系统缩放，入口 viewport 声明安全区与可用时的软键盘内容重排；页头、正文、登录和首次设置分别预留安全区，
主工作区随页面滚动。手机上的邮件诊断标签/值纵向排列，筛选控件、配置动作和确认按钮允许换行，结算选择器在
48rem 内转为单列，仍保留同一份表单、草稿与请求身份。

## 4. 视觉基底

共享 [base.css](crates/auction-web-shared/style/base.css) 的背景、文字、强调色、字体、间距与断点；表单、状态徽章和
高密度表格由 [admin.css](crates/auction-web-admin/assets/admin.css) 独立维护。控件沿用中性灰底，普通/登录输入框边界
分开；危险按钮使用深红底/白字，不直接套用较亮的错误文字色。正常、待处理和错误状态均配文字，待处理不代表成功；
浮层使用共享层级，不引入外部字体或 UI 框架。

## 5. 表格、表单与确认

表格遵守[布局契约](docs/design/table-layouts.md)：100% 容器宽、独立百分比列宽、窄屏保留行列，长值截断后可查看全文，
操作按钮可换行，配置差异、诊断和 JSON 在自己的查看区域换行。分页使用共享数字页码/省略号、权威总条数、预设及自定义
数量；数量仅接受 ASCII 正整数 i64，拒绝空白、符号、小数、指数、溢出与超过服务器上限的提交，超 offset 边界显示错误
且不发送请求，导航的可访问页上限不修改权威总数。

窄屏减少表格横向内边距，行内动作沿自己的原列纵向排列，所有表头和列顺序保持完整。触控模式使用共享
`--size-target` 的 44px 控件高度，装备多选等复选项由完整标签承接点击；密集列中的按钮宽度仍受该列约束。
用户黑名单历史保留桌面悬浮摘要，点击或键盘激活可打开共享模态详情，支持长历史滚动与关闭后的焦点恢复，
直接使用当前已加载数据，不引入额外查询。

列表统一用 `page_size`（auctions/lots/settlement-catalog 上限 100/offset 100000；users/renames/credentials/audit 与
mail 上限 200/100、offset 2147483647；deliveries 100/i64 安全乘法边界），特例键为 realtime 的 `event_page_size`/
`failure_page_size`/`lag_page_size`（200/1000000）、`proxy_page_size`（100/100000），以及完全本地切片的
`lot_page_size`/`recovery_page_size` 与 `mail_delivery_page_size`（无服务端数量上限）。每表偏好键为
`hv.admin.page-size:<scope>`，仅存展示数量；数量变更回该表首页，其他列表不复位。结算目录仍使用既有
world/auction/sequence/page 多信号同步，改变目录数量保留所选场次及两个报告的分页。代理弹窗按 lot ID、结算报告按
auction ID、邮件关联投递按 intake ID 隔离挂载。

命令交互遵循：读取权威投影 → 编辑候选 → 校验/审查 → 确认目标、版本及影响 → 冻结 `command_id`、版本 fence 与负载 →
提交 → 展示事实结果 → 刷新投影。

- 生命周期、配置、规则、凭据和恢复使用各自的 revision、fingerprint 或 fencing version，不能互相替代。
- 按钮可用性来自服务端 capability，浏览器禁用只是提示，不能代替后端校验；提交中禁用重复操作。
- 同一已提交命令重试保留原 ID 和原负载，不用新版本覆盖结果未知的旧请求；冲突后先重读权威状态再由操作员决定新命令。
- 危险动作确认说明对象、原因及后果；关闭对话框是否保留未确认命令由具体 owner 决定。
- HTTP 接受或任务重新排队不是外部发送、取件、退回、收款或交付成功。

分页会卸载旧行，已提交命令因此由 `surface/pending` 的当前路由稀疏集合持有，任务直接登记到集合 Signal 的页面 Scope。
busy 是条目字段，不逐次分配直到页面卸载才回收的 Signal。首次提交冻结完整参数和 UUID，常驻未决区展示实体、动作、
命令 ID、忙碌与未知状态；
未知状态累计（超时、断连、无效响应及未识别错误均保留，后续认证/限流拒绝不能解除），只有成功重放移除或从未未知的
明确拒绝由操作员显式关闭，没有自动重放。

冻结内容按调用点固定：拍卖生命周期存 auction ID/action/version/reason，计划修改存 auction ID/version 与三项原精度时间
（重试不再用当前时钟校验候选），lot 改价/撤回存 lot ID/action/version/price（存活行通知一律 `try_write`），凭据启停/改名
存安全凭据投影与 status/label（不含 Cookie/secret），用户论坛绑定/Key 补发撤销/拉黑存安全用户投影与 forum ID/reason
（返回 Key 直接进入稳定页面回调），内嵌装备录入存 world、已选来源的 URL/JSON、price、player（未选来源草稿不保留）。

同一实体的未决状态同时封锁不同动作的新意图；集合只保存真实已提交的工厂和冻结参数，不保存已完成成功结果或浏览历史。
创建用户、创建拍卖、投递/关联投递、规则发布及 replay 同样使用稳定页面 owner；runtime 命令随 ConfigDraft 由认证外壳持有，
站内切页保持。关闭弹窗或切换邮件详情只关闭展示，不取消未决任务；离开所属页面或明确退出的清理不代表服务端取消。
Users 创建与行命令共用同步串行门禁，手动 Key 在工厂内存中支持原样重试，生成 Key 交稳定页面一次性展示；
重新签发只替换旧 Key 并展示新值，不生成 `key_reply` 或 dry-run 任务。
规则和 runtime 的未知保存还必须冻结编辑、校验及重载入口，不能通过生成另一候选绕过原命令确认。

## 6. 关键业务工作区

### 拍卖录入与结算

`/auctions` 提供独立论坛状态区，选择当前列表页的拍卖并“刷新论坛状态”：加载、关闭、尚无镜像、失败和已发布明确区分。
该动作只 GET 本地投影，不授权或触发论坛重写；切换目标重新建立读取状态。正文详情区承接从 Public 移入的标题、
源/内容版本、同步时间、最近完整扫描及错误时间/代码，本地目标正文用原生 `details/summary` 默认折叠、`pre/code` 转义
显示 BBCode，并明确本地目标不保证与论坛实际正文逐字一致。

拍卖列表表达时间线和服务端能力，不从按钮状态推导已经开拍或结算。手工录入明确使用卖家信息，最终 COD 收件人与结算
事实由最终买家及履约 owner 决定，录入数据库不等于装备已经转入发信账号。创建/改期首次提交后冻结时间、版本与命令
身份，未编辑重试复用原负载，不因时间流逝在浏览器拦截账本重放；计划时间未编辑时保留服务端秒/亚秒精度。录入表单按
world 重建，提交中锁定世界选择，迟到响应仍核对请求 world。结算页只选择已结算轮次，报告与所选 UUID、world、sequence
对齐，页面显示后端金额事实及正负调整而不重算，recovery 操作仍需版本 fence 和证据重校验。

### 邮件诊断与投递

收件列表提供筛选、分页与安全摘要；详情绑定 intake ID，切换收件不能继续展示或操作上一封邮件。拒收说明优先使用
持久化装备诊断，再使用业务原因码，没有留存原因时明确说明而不猜测原因。提示按“具体原因、处理建议、原始安全代码”
组织；拒收、退回任务排队和退回成功是不同事实，未知外部写入结果先人工对账。原始 Cookie、装备 key、认证正文和敏感
游标不进入诊断页面（见[邮件诊断](ops/mail/diagnostics.md)）。
轮询状态同样绑定请求邮箱：切换邮箱不展示或操作旧邮箱快照，卡片本地状态按邮箱隔离；同一邮箱后台重读保留已完成状态。
`/mails` 的轮询状态卡增加“入站处理诊断”：已完成邮件游标（安全数字 MID）独立于当前处理 MID，
阶段包括拉取/恢复、读取详情、处理入站、提交批次、空闲、失败与取消。最近失败显示实际失败阶段、MID 和时间，
不把待读队首或列表显示名当作当前目标；仅加载/刷新状态时读取，明确显示 Admin/Worker 观测时间与阶段更新时间。
原始/非数字 cursor 隐藏；Worker 不可用、尚未观测和空闲分别展示，最近失败在 Worker 重启后清空。
诊断只读、不自动跳过或重发，不解释为投递完成；使用语义标题与定义列表，长数字在容器内换行，不增加滚动表或高频播报。

### Cookie 管理

`/cookies` 是统一入口，列表只显示安全元数据，不读取并回显已保存 Cookie；新 secret 只在当前输入与提交请求中使用，
不写入 URL、日志、浏览器持久化存储或普通结果 DTO。邮件导入的可选预期完整玩家名称使用带 label/`aria-describedby`
的 text 输入，关闭自动纠正、大小写及拼写检查并按原文传递，服务端独立拒绝空串、首尾空白、控制字符及超过 256 UTF-8
字节；只在导入声明预期值，标签改名不修改绑定，旧凭据保留原记录。预期值、Cookie 可用性与远端自身身份证明分开。
来源选择为“粘贴 Cookie”或“使用论坛账号密码获取”；后者用明确的论坛账号/密码 label、`username`/`current-password`
自动填充提示，不误用 Admin 登录身份。切换来源清空离开分支的敏感值，忙碌或已有未知结果时禁止切换。
游戏导入可粘贴完整论坛 CK，服务端仅保存共享认证字段；每次只写所选类型，不暗中替换另一类凭据，不向浏览器回传取得的 CK。
验证码或额外验证明确引导论坛浏览器登录后粘贴，不声称浏览器完成验证会自动解锁服务端登录。
可信页面解析器尚未支持时界面明确提示未启用内部免寄。导入表单独立累计未知结果：首次未知后全部原值
（来源、kind/world/label/player_name、密码或 Cookie）与原 UUID 锁定，输入事件处理器也拒绝变更，仅能原样手动重试；后续 401、429、前置
校验或 `credential_conflict` 不证明先前未提交，任意 409 均不解除锁定，只有明确成功后清空表单并释放原命令。
手动校验显示当次登录有效、失效或暂无法确认及检查时间及 shared 游戏 Cookie 的主世界/异世界结果，同一凭据版本改变后
隐藏旧结果；校验只读，不自动启停或重试，也不证明发帖或发信权限。

### 规则发布

按语言加载正文与 revision，编辑、预览、校验、发布分开，只有最近已校验的当前候选允许发布；修改草稿后旧校验结果失效，
校验/发布中禁止切换语言，迟到响应不能覆盖另一语言内容。发布使用稳定命令 ID 和 revision fence，版本冲突不得静默覆盖。

### 运行配置

邮件分组增加七类发送间隔：超价、账号、寄售回执、结算款项、装备交付、告警、手工邮件。原生数字控件范围 0–86400 秒，
默认 0；说明明确同类发送起点间距而非轮询周期、跨世界共用、不绕过串行/远端限速、保存后重启 Worker。
只有 managed 接管时编辑生效，沿用草稿、差异确认与错误定位，旧文档缺省展示 0，不暗中更改部署开关。

参数配置中的“拍卖控制”“Worker 入站与发件人收录”“装备收录”使用原生 `details/summary`，默认折叠，点击标题展开。

配置草稿保留在当前认证外壳内，站内切页可继续编辑、退出后清理，不进入 localStorage/sessionStorage。数值输入保留原始
候选，解析失败不能沿用旧值冒充有效。保存前逐项审查安全差异及影响范围，明确区分部署配置、runtime 接管组和数据库业务
世界开关；保存只证明持久化，不等于热加载，新经济模板只用于后续新建拍卖。页面不直接读写或拼接敏感 TOML。

论坛标色编辑器只使用服务端统一装备词典的只读投影，浏览器不维护另一份分类、品质、种类、材质或词缀表。
GET、校验和保存沿用既有配置接口，显式传 `include_equipment_taxonomy=true` 请求 `equipment_taxonomy`；
缺少词典、结构无效、重复名称或大类引用不一致时明确返回配置响应错误，不回退本地旧表。
词典的 `revision` 独立于 runtime 文档和 fingerprint，既不进入保存负载、稳定命令摘要，也不进入装备快照。
同一文档 fingerprint 下词典更新仅刷新候选，不覆盖会话草稿或制造待保存修改；非法数字等编辑中间态仍参与草稿比较。
[options](crates/auction-web-admin/src/app/operations/config/form/equipment_colors/options) 只负责对投影计算筛选和去重并集。

装备类型、装备种类、品质和前后缀均使用带 `fieldset/legend` 的原生复选框组，可直接点击标签或使用键盘切换；
前三项空选表示全部，提供“全部”按钮清空该维度。类型、种类、品质同维多选取并集，跨维仍需同时匹配，
不把一个多选规则拆成多条规则。旧单值回填为一个已选项；保存写 `categories/equipment_types/qualities` 数组，
并清空对应旧单值，导入导出、顺序及首条匹配优先保持原有语义。唯一保真例外是未主动修改的旧材质单值：
继续按旧单值保存并显示“精确旧值”，用户清空或重新选择种类后才按新材质族语义保存。

品质推荐候选由服务端筛选为 `Peerless`、`Legendary`、`Magnificent`；已有规则中的其它已选品质继续显示，
直到用户手动取消。该候选范围独立于领域名称解析和自动收件品质策略。

多选大类时展示各大类兼容种类与词缀的去重并集；未选大类时取全部类别的并集，已选种类继续约束词缀候选。
种类候选中，武器、法杖与盾牌使用词典中的完整名称；Cloth/Light/Heavy 只使用服务端单独提供的护甲种类族，
如 `Phase`、`Shade`、`Power`，并显示“全部部位”。只有这三类护甲具有部位词，不从槽位表生成种类与部位组合候选。
已有规则的 `Phase Robe` 等护甲完整名继续作为选中值回显并保持精确匹配，手动取消后不再作为新候选。
前后缀按投影中的种类或材质精确名称关联，未知完整名称不猜测成某个材质族。
配置中已出现、经服务端领域有限语法识别的完整名，通过独立 `resolved_kinds` 提供材质、部位及词缀候选；
与确证 `kinds`、材质族三者名称互斥，有限集合最多 16 项，按规范名称去重。页面仅将它们纳入已有精确种类的词缀关联，
仍不复制有限语法或把这些名称混入确证目录；校验响应也按尚未保存的候选文档补充。
后续 GET 若因外部配置变化不再包含草稿使用的有限种类，同一 revision 下只保留草稿仍选中的旧权威候选，
与新响应按规范名称去重且新项优先；revision 变化时遵循新投影。该合并仅存在于元数据，不改变业务草稿或 dirty 比较。
切换分类或种类只更新推荐候选，不删除任何另一维的已选值；未知、历史及暂不相容的种类和词缀都原样保留并继续可见，
由用户手动取消。后缀继续兼容 `the `/`The ` 前导词。服务端推荐候选不扩大自动收件允许策略；
规则的权威匹配由 application 的论坛标色 owner 执行，词典归属和 Wiki 依据见
[领域模块](crates/auction-domain/README.md)及[装备录入不变量](docs/contracts/invariants.md#i-05a-admin-装备录入的敏感边界和原子集合)。

### 审计与实时运维

审计仅追加式事实的安全读取，不提供历史编辑，筛选提交后查询。Realtime 运维展示安全元数据、lag/failure 与受控
replay，未采集指标明确标注，未实现的广播能力不伪装成功。Dashboard 不以本地示例数据填充缺失能力，自动轮询遵守页面
可见性及卸载清理。
轮询间隔变化或关闭时立即取消旧页面任务，不等待它走完原有周期；新间隔仍从头计时，隐藏期间仍暂停剩余分片。
该取消只释放失效调度循环，不改变已发出读取的结果处理，也不补发旧间隔的轮询。
隐藏等待以 Future 独占登记持有最新 Waker；重复 poll 不追加登记，完成或取消立即移除。
恢复可见后若尚未 poll 就再次隐藏，同一 Future 会恢复登记；页面监听器不强持有已取消 Future 的 Waker。

## 7. 首次设置不是正式 Admin 页面

`/setup` 的 UI 源码位于本 crate，但由 [auction-setup](crates/auction-setup/README.md) 的独立设置服务提供，正式 Admin
HTTP 不开放该入口，设置使用一次性部署码、不复用普通 Admin session。先验证部署码，再填写数据库、管理员及运行配置；
密码确认只在浏览器校验、不进入 DTO，敏感值只存页面内存。保存超时或返回 `setup_outcome_unknown` 时清空敏感值并锁定
页面，要求核对现场，不把刷新当作安全重试；合并模式的空库初始化与启动必须有额外明确授权，保存响应不是进程 readiness。
HTTP Origin 仅接受规范的 `localhost`、`127.0.0.1` 与 `[::1]` 回环地址；其它主机必须使用 HTTPS。

## 8. 文案、可访问性与错误边界

Admin 默认 `zh-CN`，支持 `en`、`zh-CN`、`zh-TW`、`ja`、`ko`；文案来自本 crate 的五份 Fluent 资源，不借用 Public 译文，
语言机制共享，偏好键仍为 `hv.lang`。错误按稳定 code 映射，不展示后端原始敏感错误。

成功/进行中反馈与失败反馈分别使用适当的 `status`/`alert` 语义，状态颜色必须配合文字。弹窗提供初始聚焦、Tab 循环、
背景滚动锁及关闭后焦点恢复，忙态关闭守卫与提交守卫一致；换页后聚焦主内容，错误摘要可定位并展开相应字段。读取失败
不等于空数据、未登录或任务失败，`501` 档位缺失、`409` 并发冲突、`401` 认证状态及 `503/504` 依赖错误按各自边界处理；
启动超过 15 秒只提示加载较慢，真实 WASM panic 才显示运行异常。

## 9. 构建与维护

静态检查用 `bash ci/checks/check.sh i18n` 和 `cargo check --locked -p auction-web-admin --target wasm32-unknown-unknown`；
`bash ci/release/web-bundle.sh admin` 只生成 Admin 页面，上线还需重编并部署启用 `web-embed` 的宿主（见[开发指南](docs/guide/development.md)）。
分体 Public 不含管理资源，合并制品也保持 router 隔离。修改同步模块说明、五语言与受影响契约，共享控件变化核对两端；
技术栈和默认测试限制见[协作规范](AGENTS.md#web-规则)。
