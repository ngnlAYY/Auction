# Admin 管理端设计

[系统设计](../../docs/architecture.md) · [模块说明](README.md) · [文档导航](../../docs/README.md) · [独立的 Public 设计](../auction-web-public/DESIGN.md)

本页描述现有 Admin 界面；操作授权与运行证据另行确认，源码和线上制品边界见[状态页](../../docs/status.md)。

## 1. 定位与隔离

管理端服务可信操作员，目标是清楚地区分当前事实、候选修改、已接受命令和外部最终结果。
界面优先保证可审查、可追踪、可恢复，而不是复用 Public 的竞价看板或把危险动作包装为普通快捷按钮。

管理页面及认证内状态由 [src/app/](src/app/) 拥有，API/命令提交由 [src/api/](src/api/) 拥有；
专属样式为 [admin.css](assets/admin.css)，文案为 [i18n/](i18n/)，构建与嵌入入口见[模块说明](README.md)。
Admin 不导入 Public。其 `/rules` 别名转到独立的校验/发布页；共享层不拥有权限、配置草稿或业务命令。

## 2. 信息架构

| 页面族 | 入口示例 | 操作员关注点 |
| --- | --- | --- |
| 总览 | `/` | 单份安全快照、进程与 Worker、邮件轮询、凭据可用性及任务水位 |
| 拍卖与拍品 | `/auctions`、`/auctions/{auction_id}/lots` | 创建、计划时间、生命周期、手工录入、起拍价及撤回 |
| 结算与恢复 | `/settlement` | 已结算轮次、金额事实、交付及 recovery 状态 |
| 邮件与投递 | `/mails`、`/deliveries` | 收件诊断、关联任务、轮询、重试及人工对账 |
| 用户与改名 | `/users`、`/renames` | 账号投影、登录 Key、论坛身份、黑名单及改名历史 |
| 外部凭据 | `/cookies` | 论坛/游戏 Cookie 的安全录入、状态及手动只读校验 |
| 规则内容 | `/rules-content` | 语言、版本、正文草稿、校验、预览与发布 |
| 运行配置 | `/config` | 候选配置、版本指纹、实际差异、影响范围及重启要求 |
| 实时与审计 | `/outbox`、`/audit` | 安全事件元数据、lag/failure、受控 replay 及追加式审计读取 |

上表使用正式入口；兼容别名与导航顺序以源码为准。完整登记见 [HTTP 契约](../../docs/contracts/routes.md)
和 [入口清单](../auction-http/src/assets/routes.rs)。`/status` 等保留入口不因存在路由就进入主导航。

## 3. 外壳、认证与布局

正式页面先通过 Admin 会话外壳，不允许未认证的深链接或未知路由绕过会话加载与错误处理。
登录使用现有认证交换，业务写入携带所需 CSRF；浏览器不自行判断权限或数据库资格。
会话读取失败显示错误和重试，只有权威会话结果确认未认证才回到登录页。

桌面布局：

```text
管理端标识                                  语言 / 操作员 / 退出
─────────────────────────────────────────────────────────────
扁平导航        │ 页面标题 / 主要操作
                │ 筛选 / 当前版本或状态摘要
                │ 列表、表单或报表
                │ 分页 / 命令反馈
```

- `admin-shell` 的桌面侧栏宽度为现有 `12rem`，活动入口使用强调色背景与可访问的当前页标记。
- 窄屏改为顶部折叠菜单，主内容不继续被固定侧栏挤压；不套用 Public 页头和世界切换器。
- 主区保留 `min-inline-size: 0` 与受控内边距；操作栏和筛选可换行，不以横向滚动容纳宽表。
- 登录页采用最大 `22rem` 的窄表单，不增加装饰卡片边框或无意义的整页溢出。
- Dashboard 按业务分组响应式分栏；结算页始终为“轮次选择在上、报告在下”，不把长报告塞进并列窄面板。
- 主要动作靠近页面标题或目标记录，危险动作和异步任务结果必须能追溯到对应实体。

## 4. 视觉基底

共享 [base.css](../auction-web-shared/style/base.css) 的背景、文字、强调色、字体、间距与断点；
表单、状态徽章和高密度表格由 [admin.css](assets/admin.css) 独立维护。
控件沿用中性灰底，普通/登录输入框边界分开；危险按钮使用深红底/白字，不能直接套用较亮的错误文字色。
正常、待处理和错误状态均配文字，待处理不代表成功。浮层使用共享层级，不引入外部字体或 UI 框架。

## 5. 表格、表单与确认

表格遵守[布局契约](../../docs/table-layouts.md)：100% 容器宽、独立百分比列宽、窄屏保留行列，
长值截断后可查看全文，操作按钮可换行。配置差异、诊断和 JSON 在自己的查看区域换行，不隐藏审查信息。

命令交互遵循：

```text
读取权威投影 → 编辑候选 → 校验/审查 → 确认目标、版本及影响
                                         ↓
                         冻结 command_id、版本 fence 与负载
                                         ↓
                            提交 → 展示事实结果 → 刷新投影
```

- 生命周期、配置、规则、凭据和恢复使用各自的 revision、fingerprint 或 fencing version，不能互相替代。
- 按钮可用性来自服务端 capability；浏览器禁用只是提示，不能代替后端校验。
- 提交中禁用重复操作；同一已提交命令重试保留原 ID 和原负载，不用新版本覆盖结果未知的旧请求。
- 冲突后先重读权威状态，再由操作员决定新的命令；不自动覆盖并发修改。
- 危险动作确认说明对象、原因及后果。关闭对话框是否保留未确认命令由具体 owner 决定，不能全局一律清空。
- HTTP 接受或任务重新排队不是外部发送、取件、退回、收款或交付成功。

## 6. 关键业务工作区

### 拍卖、录入与结算

拍卖列表表达时间线和服务端能力，不从按钮状态推导已经开拍或结算。手工录入明确使用卖家信息，
最终 COD 收件人与结算事实由最终买家及履约 owner 决定；录入数据库不等于装备已经转入发信账号。
创建/改期首次提交后冻结时间、版本与命令身份；未编辑重试复用原负载，不因时间流逝在浏览器拦截账本重放。
计划时间未编辑时保留服务端秒/亚秒精度。录入表单按 world 重建，提交中锁定世界选择，迟到响应仍核对请求 world。

结算页只选择已结算轮次，报告与所选 UUID、world、sequence 对齐。页面显示后端金额事实及正负调整，
不在浏览器重算结算金额；recovery 操作仍需版本 fence 和证据重校验。

### 邮件诊断与投递

收件列表提供筛选、分页与安全摘要；详情绑定 intake ID，切换收件不能继续展示或操作上一封邮件。
拒收说明优先使用持久化装备诊断，再使用业务原因码；没有留存原因时明确说明，不猜测 Cookie、品质或网络问题。

提示按“具体原因、处理建议、原始安全代码”组织。拒收、退回任务排队和退回成功是不同事实。
登录失败、采集时间异常、业务规则拒收和证据保存失败分别说明；未知外部写入结果先人工对账，不盲目重发。
原始 Cookie、装备 key、认证正文和敏感游标不进入诊断页面，边界见 [邮件诊断](../../ops/mail-diagnostics.md)。

### Cookie 管理

`/cookies` 是统一入口，列表只显示安全元数据；不能读取并回显已保存 Cookie。
新 secret 只在当前输入与提交请求中使用，不能写入 URL、日志、浏览器持久化存储或普通结果 DTO。

手动校验显示当次登录有效、失效或暂无法确认及检查时间；shared 游戏 Cookie 分别列出主世界、异世界结果。
同一凭据版本改变后隐藏旧检查结果。校验是只读操作，不自动启停、不自动重试，也不证明发帖或发信权限。
凭据切换与 Worker 重启要求遵循后端唯一 active 约束，不提供自动换备用 Cookie 的界面承诺。

### 规则发布

按语言加载正文与 revision，编辑、预览、校验、发布分开；只有最近已校验的当前候选允许发布。
修改草稿后旧校验结果失效，校验/发布中禁止切换语言，迟到响应不能覆盖另一语言内容。
发布使用稳定命令 ID 和 revision fence，版本冲突不得静默覆盖。预览使用安全 Markdown，不执行原始 HTML。

### 运行配置

配置草稿保留在当前认证外壳内，站内切页可继续编辑；退出后清理，不进入 localStorage/sessionStorage。
数值输入保留原始候选，解析失败不能沿用旧值冒充有效；字段旁错误与顶部可定位摘要同时提供。
保存前逐项审查安全差异及影响范围，明确区分部署配置、runtime 接管组和数据库业务世界开关。

保存只证明持久化，不等于热加载；按受影响角色提示重启。新经济模板只用于后续新建拍卖，不能回写已有快照。
页面不直接读取、写入或拼接敏感 TOML。

### 审计与实时运维

审计仅追加式事实的安全读取，不提供历史编辑。筛选提交后查询，避免每次键入都发请求。
Realtime 运维展示安全元数据、lag/failure 与受控 replay；未采集指标明确标注，未实现的广播能力不伪装成成功。
Dashboard 不以本地示例数据填充缺失能力，自动轮询遵守页面可见性及卸载清理。

## 7. 首次设置不是正式 Admin 页面

`/setup` 的 UI 源码位于本 crate，但由 [auction-setup](../auction-setup/README.md) 的独立设置服务提供，
正式 Admin HTTP 不开放该入口。设置使用一次性部署码，不复用普通 Admin session。

先验证部署码，再填写数据库、管理员及运行配置。密码确认只在浏览器校验，不进入 DTO；敏感值只存页面内存。
保存超时或返回 `setup_outcome_unknown` 时清空敏感值并锁定页面，要求核对现场，不把刷新当作安全重试。
合并模式的空库初始化与启动必须有额外明确授权；保存响应不是进程 readiness。

## 8. 文案、可访问性与错误边界

Admin 默认 `zh-CN`，支持 `en`、`zh-CN`、`zh-TW`、`ja`、`ko`。界面文案来自本 crate 的五份 Fluent 资源，
不借用 Public 译文；语言机制共享，偏好键仍为 `hv.lang`。错误按稳定 code 映射，不展示后端原始敏感错误。

成功/进行中反馈与失败反馈分别使用适当的 `status`/`alert` 语义；状态颜色必须配合文字。
弹窗提供初始聚焦、Tab 循环、背景滚动锁及关闭后焦点恢复；忙态关闭守卫与提交守卫一致。
导航换页后聚焦主内容，刷新和字段校验不无故抢焦点；错误摘要可定位并展开相应字段。

读取失败不等于空数据、未登录或任务失败。`501` 档位缺失、`409` 并发冲突、`401` 认证状态及 `503/504`
依赖错误按各自边界处理。启动超过 15 秒只提示加载较慢；真实 WASM panic 才显示运行异常。

## 9. 构建与维护

静态检查用 `just i18n-check` 和 `cargo check --locked -p auction-web-admin --target wasm32-unknown-unknown`；
`just web-build-admin` 只生成 Admin 页面，上线还需重编并部署启用 `web-embed` 的宿主，见[开发指南](../../docs/development.md)。
分体 Public 不含管理资源，合并制品也保持 router 隔离。修改同步模块说明、五语言与受影响契约，
共享控件变化核对两端；技术栈和默认测试限制见[协作规范](../../AGENTS.md#web-规则)。
