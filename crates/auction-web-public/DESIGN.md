# Public 公开端设计

[系统设计](../../docs/architecture.md) · [模块说明](README.md) · [文档导航](../../docs/README.md) · [独立的 Admin 设计](../auction-web-admin/DESIGN.md)

本页描述现有 Public 界面。源码、内嵌产物与线上页面可能版本不同，验收边界见[状态页](../../docs/status.md)。

## 1. 定位与隔离

公开端服务浏览者、竞买人及查看寄售结果的卖家。首要任务是找到装备、理解价格与截止时间、明确确认出价，
并在网络恢复后重新取得权威状态。它不是管理控制台，不展示凭据管理、Worker 操作、审计编辑或运行配置入口。

页面与交互由 [src/app/](src/app/) 拥有，API/实时恢复由 [src/api/](src/api/) 拥有；
专属样式为 [public.css](assets/public.css)，文案为 [i18n/](i18n/)。构建与嵌入入口见[模块说明](README.md)。
Public 不导入 Admin 页面/资源；共享层只提供通用机制，业务字段、列宽、竞价状态和文案留在本端。

## 2. 信息架构

| 页面族 | 入口示例 | 核心内容 |
| --- | --- | --- |
| 当前拍卖 | `/` | 世界、当前/预览/历史视图、场次摘要、分类筛选和拍品目录 |
| 拍卖历史 | `/auctions` | 世界与状态筛选、分页、拍品及竞价记录入口 |
| 装备详情 | `/lots/{lot_id}` | 装备安全投影、价格、截止时间、竞价历史和本人代理状态 |
| 竞价记录 | `/bidlog` | 场次/拍品筛选、玩家、来源与持久化竞价事实 |
| 成交历史 | `/history` | 装备、日期、价格、买卖方筛选及成交统计 |
| 论坛同步 | `/forum` | 只读同步开关、同步摘要、主题链接、真实处理楼层及更新时间；无正文或手动重试按钮 |
| 公开内容 | `/rules`、`/blacklist`、`/compensation-pool` | 已发布规则、禁拍名单与补偿流水 |
| 登录与账户 | `/login`、`/me` | Public Key 登录、账号竞价警告渠道、本人竞价及代理授权 |
| 服务说明 | `/status` | 静态产品说明，不另建实时连接 |

这里只概括页面职责，不替代完整路由清单。兼容别名、参数与后端 SPA 入口见
[路由契约](../../docs/contracts/routes.md) 和 [入口清单](../auction-http/src/assets/routes.rs)。
导航只突出正式入口，不能因为保留了别名就重复增加菜单项。

## 3. 外壳与布局

桌面信息层次：

```text
品牌 / 主导航                         世界 / 连接状态 / 刷新 / 语言 / 账户
─────────────────────────────────────────────────────────────────────
页面标题或拍卖摘要
筛选与上下文
拍品表、详情、账户或内容文档
分页与操作反馈
```

- 页头由 `public-shell` 持有，品牌使用强调色；当前导航项使用可见标记及 `aria-current`。
- 世界选择与账户状态保持可辨认，不让用户在不清楚当前世界或身份时提交竞价。
- 窄屏主导航折叠为两列菜单，展开状态通过 `aria-expanded` 表达；刷新、语言与账户保留独立控制区。
- 正文占用可用容器宽度。筛选和操作控件可换行，不能靠压缩到不可操作的尺寸维持单行。
- 规则正文使用自己的 `public-rules-page` 容器及安全 Markdown 块，不套入管理端卡片或编辑器布局。
- 论坛状态文字靠左，“查看论坛帖子”位于同一状态行右侧；空间不足时自然换行，不撑宽页面。
  下方只保留处理楼层、更新时间及简短延迟提醒；正文、版本及诊断详情归 Admin 拍卖管理。
- 黑名单页保留标题、名单或空态、分页；不显示额外的数据库 ID 说明段。表格仍显示 MoogleMail 玩家名称，
  不把姓名回退为内部数据库 ID；显示名不改变黑名单资格校验。

## 4. 视觉基底

沿用深色、紧凑、以数据为主的界面，不增加外部字体或主题框架。背景/容器层级、主次文字、金色品牌强调、
蓝色链接、语义状态及系统字体均使用[共享 base.css](../auction-web-shared/style/base.css)变量；具体值由样式维护。
状态颜色须配明确文字。`public-*` 布局和交互状态留在 `public.css`，不引入 `admin-*` 选择器；
间距、控件尺寸和断点复用共享体系，不为单页增加新的断点档位。

## 5. 表格与信息密度

表格遵守[布局契约](../../docs/table-layouts.md)：100% 容器宽、独立百分比列宽、窄屏保留表头/行列，
不改卡片或横向滚动。长文本提供完整值查看，复杂文本支持键盘/触控。金额对齐并提示完整 Credits，
表头/caption/可访问名称保留真实字段关系，不用 CSS 伪文本替代。装备链接只消费安全 DTO，空链接不伪造入口。

首页装备目录（含历史目录）、往期拍卖、出价记录、装备详情竞价历史、历史成交价、黑名单、补偿池批次与展开流水
统一使用「总数 → 每页数量 → 前后按钮及数字页码 → 跳页」控件。默认 10 条，保留 10/20/50/100 预设，
同时提供自定义输入及应用按钮，取消 200 条业务上限，只接受 `i64` 可表示的正整数；空值、0、符号、小数、科学计数法、空白及数值溢出不提交、不保存。
输入失焦或提交后提示错误，修正后清除；提示在自定义输入所在控件下方左对齐，关联输入的可访问描述，不继承空态面板的居中样式。
数量原样交给后端，不截断成预设值；大页可能显著增加数据库读取、响应内存与浏览器渲染成本，请求仍受既有超时约束。
数字页码显示首尾与当前页附近的有界窗口，其余用不可点击的省略号表示。无权威总数时不伪造总数，保留已有下一页探测边界。
导航另受各 API 既有 offset 上限约束，但显示的总条数不缩减。
改变数量回到第 1 页，保留筛选；`page_size` 与页码写入 URL，支持刷新、分享和前进/后退。
URL 明确数量优先，非法数量回退 10；未提供时读取本地偏好。序列化数量保留 10，改变偏好前固定离开条目的数量，避免返回时受新偏好影响。
用户主动确认才保存 `localStorage` 的 `hv.public.page-size`，全部主列表共享；访问链接不覆盖偏好，存储损坏或不可用退回 10。
外壳首页入口只保留世界参数，点击时恢复最新偏好，不将外壳较早渲染的数量冻结在链接中。
补偿池展开场次使用 `auction`，流水独立使用 `movement_page`/`movement_page_size` 与 `hv.public.movement-page-size`；
改变批次分页收起流水。偏好读取/保存由 `surface/pagination/preferences.rs` 拥有。
重读期间不把旧页元数据用于新分页状态纠偏，出价记录筛选工具条保持挂载，不因翻页重读失焦。
原生 select、可见焦点、当前页 `aria-current=page` 与状态播报保留；
窄屏控件自然换行，不撑宽表格。账户和 Admin 未接入此变体，保持原分页布局。

## 6. 竞价与代理交互

浏览器表达意图，不计算最终竞价结果，也不复刻领域状态机。

```text
选择拍品 → 读取权威状态/资格 → 输入金额 → 明确确认
                                       ↓
                             冻结 command_id 与负载
                                       ↓
                         提交 → 展示结果 → 重读权威快照
```

- 普通出价输入为不带后缀的 K 单位整数，发送前显示实际 Credits 金额和独立确认步骤。
- 代理表单显示 Fast/Slow、上限、配额与服务端 capability；最终阶段不能选择新建 Slow。
- 新输入遵守既有 1K 网格与 1B 上限，非法输入直接说明，不静默取整；服务端仍是最终权威。
- 提交中锁定重复动作。结果未知时保留原命令 ID、金额、模式与目标，不用刷新后的新状态改写旧请求。
- 成功面板展示服务端结果，随后更新权威读取；不能凭本地按钮点击就显示领先、成交或扣款成功。
- 表单状态以拍品及当前用户隔离；切换目标或身份不沿用上一用户的草稿和任务。
- 登录返回仅允许受限同源路径；`/me` 的竞价、代理分页与筛选恢复遵守既有 URL 契约。

### 6.1 装备标记与超价提醒

- 目录 preview/live 与装备详情提供原生 `button type=button`，`aria-pressed` 表达标记状态，名称含装备编号。
  动作仍位于既有动作列或详情操作区，不新增列；保留可见焦点、触控尺寸、忙碌反馈和可见错误。
  匿名只显示登录入口，会话失败不伪装匿名。所有文案由五语言 Fluent 提供，无 JavaScript/Invoker API 或新依赖。
- 服务器是唯一权威。每个 user UUID + auction UUID 的 keyed owner 只读取一次整场集合，分页和每行共享读取，
  不做 N+1。请求完成前后核对用户，拍卖切换或账号改变销毁旧宿主，迟到响应不得污染新身份或新拍卖。
- `hv.public.lot-watches.v1:<user UUID>:<auction UUID>` 仅保存集合中的用户/拍卖/标的 UUID、布尔标记、渠道与版本。
  不保存凭据、装备链接、代理上限。缓存受限、损坏或超过大小限制时忽略，不改变服务器命令结果。
  缓存展示明确为未同步；只有当前完整 GET 成功且刷新代数对齐时才能生成修改版本。
  缺项才推导 false/version 0，取消返回的 false/正版本墓碑必须保留；缓存永不批量上传覆盖服务器。
- PUT 冻结 `command_id`、目标标记、`mm` 与 `expected_version`。未知结果只重试完整原命令，不改 ID 或版本；
  内存中的待定命令由整场宿主持有，翻页或分类卸载单行不丢失。身份/拍卖宿主销毁或整页重载不持久化命令，
  返回页面重新读取权威集合，不自动重放。409 明确提示用户刷新、确认状态并重新操作，不自动覆盖。
  GET 失败/加载中不能发起新修改，但未知命令仍可原样重试以确认结果。
- 标记成功（包括幂等重放）后重读集合，不直接把命令历史响应当最新集合。普通和代理命令成功复用全局刷新代数重读；
  普通竞价不会自动标记，新建代理自动标记由后端决定，既有代理查询/降额/自动追价不会在前端强制置 true。
- 标记 API 的 `channel=mm` 保留为兼容占位，不开放每件装备 PM 设置，也不更改旧未知命令重试语义。
  生效渠道由账号偏好统一决定。只有真实领先后被超越，每个领先周期一次；非领先时的价格变化不通知，
  重新领先后再次被超越可再提醒。取消后的待发送资格由后端处理；已经开始远端发送的通知无法撤回。
  通知失败不撤销已接受竞价，浏览器在线不是通知前提。
- `/me` 顶部、竞价与代理列表之前提供 `outbid-notifications` 稳定锚点。原生 fieldset/legend 包含
  MoogleMail 与论坛 PM 两个互斥 radio、可见 for/id label 和明确保存按钮；保留键盘导航、焦点描边、
  aria-describedby 与动态 aria-live 反馈，保存中禁重复提交。标记说明链接 `/me#outbid-notifications`。
- 偏好由 `GET/PUT /api/v1/me/lot-watch-preference` 权威维护，默认 MM 也必须由首次 GET 确认。
  同源传输消费冻结 contracts DTO，严格验证 data 字段、当前 user_id、mm/pm 和完整正 i64 版本，
  不经过 JS 浮点。未成功读取不能保存，读取失败提供重试，不显示假成功或游客偏好。
- 表单作为以 user_id keyed 的独立宿主，稳定挂载在竞价分页的 loading/error 分支之外；翻页不丢待定命令。
  PUT 冻结 command_id/channel/expected_version，未知结果保留完整原 payload 原样重试，不生成新 ID。
  未知状态跨同一命令的重试累计；后续 429 等前置拒绝不能降级为确定失败、开放刷新或丢弃原负载。
  只有原命令确认成功或明确 409 才解除未知状态；409 提示用户显式 GET 刷新再确认新意图。
  从未出现未知结果的确定性失败同样先刷新。确认命令后重读当前偏好，
  避免幂等历史结果覆盖新状态。每次请求前后核对会话，跨账号或登出旧响应不得污染新身份。
  路由离开/重载销毁内存意图，返回先 GET，不自动重放；待定命令从不存 localStorage。
- 偏好在服务器跨设备同步，仅影响已标记装备的后续反超警告，不影响结算或 COD。
  已排队通知按原渠道处理，切换不补发、不另发、不撤回旧队列；五语言帮助文案明确这些边界。
  保存成功只表示偏好已保存，不承诺可送达；论坛 PM 需要已绑定的论坛账号，不可投递时不会自动改发 MM。
  通知异步处理可能延迟，当前状态以网站为准。前端不提供绑定流程、不收集 PM 地址，也不以游戏名寻址；
  后端使用稳定论坛账号标识，缺失时记录未发送事实而不回滚出价。偏好 DTO 保持原三字段。

## 7. 数据、时间与实时状态

- 初次读取、刷新、空结果、失败与能力缺失是不同状态；网络错误不能冒充匿名或空表。
- 筛选和分页由页面 owner 与 URL 双向同步，刷新、分享和浏览器前进/后退保持上下文。
- 倒计时使用服务端时间校准，仅作显示；拍卖截止、最终阶段和资格由后端决定。
- WebSocket 是已提交事件的通知入口，不承担竞价写入。sequence 与实体 version 不能混用。
- 跳号、重连或服务端要求重新读取时，通过 HTTP Catch-up 与权威快照恢复，不从通知负载猜测下一口价格。
- 页头连接徽章统一播报连接状态，不在每张表重复播报，也不因页面增加而复制连接。
- 正常静默不等于断线；浏览器不能因为看不到协议 Ping/Pong 而把空闲拍卖判为连接失败。
- `501 feature_not_supported` 属于档位限制，不提供无意义重试；规则缺失的 `rules_unavailable`
  需要发布正式正文，反复读取不能生成规则，也不能用示例正文伪装成已发布内容。

详细恢复、事件边界与错误码见 [事件契约](../../docs/contracts/events.md)、[HTTP 契约](../../docs/contracts/routes.md)。

## 8. 文案、可访问性与安全

五语言为 `en`、`zh-CN`、`zh-TW`、`ja`、`ko`，Public 默认 `en`。界面文案由本 surface 的 Fluent 资源提供；
新增或删除消息键时同步五份资源。共享层只提供语言选择机制，偏好键固定 `hv.lang`。
正式规则正文来自已发布的规则 API，不把界面译文当作规则正文来源。

页面保留跳转主内容入口、可见焦点和语义标题；真正 SPA 换页后聚焦主内容，原地刷新不抢焦点。
竞价弹窗提供初始聚焦、Tab 循环、背景滚动锁和关闭后的焦点恢复；忙态遵守关闭守卫，不重复提交。
成功/进行中反馈与错误反馈使用相应的 `status`/`alert` 语义。

Markdown 原始 HTML 只作转义文本展示，链接遵守协议白名单。登录 Key 只用于当前认证流程并按既有逻辑清理；
敏感装备 URL 不进入日志、审计或浏览器持久化缓存。数据库记录与外部凭据不进入本 crate。

## 9. 构建与维护

静态检查用 `just i18n-check` 和 `cargo check --locked -p auction-web-public --target wasm32-unknown-unknown`；
`just web-build-public` 生成页面产物，上线还需重编并部署启用 `web-embed` 的 Public 宿主，见[开发指南](../../docs/development.md)。
页面变化同步本设计、模块说明、五语言及受影响表格/路由；共享组件变化核对两端，但不合并业务外壳。
技术栈和默认测试限制见[协作规范](../../AGENTS.md#web-规则)。账号渠道组件的整合检查、复审与验证限制
统一登记在[状态页](../../docs/status.md#本轮静态检查)；静态检查不代表浏览器、实际发信或生产验收。
