# 公开端浏览器界面

Dioxus 客户端渲染的公开端 SPA。`Route` 枚举冻结 15 条路径，其中 `/forum` 是独立论坛同步页；
修改前必须确认 [`docs/contracts/routes.md`](../../docs/contracts/routes.md) 的 URL 契约，并同步
`auction-http/src/assets/routes.rs` 的后端入口清单。

- `src/main.rs`：薄启动入口。
- `src/api/`：按 `auction/`、`content/`、`identity/` 分组的同源 Public API DTO 解码与请求；
  `clock.rs` 负责服务端时间校准和 GET 边界，`model.rs` 负责 lot 展示模型，`queries.rs` 负责
  拍卖、lot、竞价日志和价格历史查询，`mod.rs` 只保留模块装配与稳定导出，不接触存储模型。
- `src/app/`：按相同 owner 分组的公开端路由、页面和交互组件；`surface/` 进一步按路由、
  看板、目录、页面和查询状态拆分跨页面职责；`surface/board/` 将看板入口、世界选择、实时刷新、
  拍卖数据和预览/历史视图切换分开；`surface/catalog/` 继续按表格、竞价动作、行组件
  和展示映射拆分；`surface/pages/` 将历史列表、lot 详情/竞价、通用重试和路由薄包装分开；价格历史筛选器在
  `auction/reads/history/filters/` 内进一步拆分表单控件、错误模型和输入规范化；
  `auction/commands/` 将普通竞价、代理入口/创建表单/降低表单/成功反馈和共用命令状态/错误映射分开；
  `shared/` 只保存本 surface 内真正通用的基础组件。
- `src/app/content/forum.rs`：独立 `/forum` 页面，按所选世界读取当前拍卖的 P15 论坛镜像；发布后只
  显示可点击的帖子位置和持久化的“已更新到 #xx”真实处理楼层，首页不再读取论坛同步状态。发布前
  每 2 秒、发布后每 30 秒读取本地投影，明确失败时暂停并提供人工重试。
- `assets/public.css`：公开端 surface 样式，持有公共拍卖页的 BEM 类名与视觉契约。
- `i18n/*.ftl`：5 种语言的 Fluent 译文（`en`、`zh-CN`、`zh-TW`、`ja`、`ko`），默认英文。

## 国际化

所有用户可见文案都经 `t!` 从 `i18n/*.ftl` 取用，组件里不得硬编码字符串。译文以
`include_str!` 编译期内嵌，首屏不额外请求语言资源。

Fluent 消息 ID 不允许包含点号，使用 `nav-home` 而不是 `nav.home`。

`t!` 在键缺失时 **panic**，因此新增文案必须同步更新全部 5 个 `*.ftl`；缺一种语言就会让该
语言下的页面崩溃。语言集合、偏好持久化和 `<html lang>` 同步由 `auction-web-shared` 提供，
本 crate 只拥有自己的译文。规则正文请求显式携带当前 locale，并把 locale 作为响应式资源依赖；
切换语言会取消/替换旧读取，避免界面文案与规则正文串语言。规则成功态继续由
`public-rules-page` 拥有容器，并通过无外层主题的安全 Markdown 块保持冻结宽度和默认排版。
  设计变量来自 `auction-web-shared`。

构建：

```bash
just web-build-public   # 通过 dx bundle 复制到稳定嵌入目录
just web-serve-public   # 本地开发监听
```

`just web-build-public` 内部先执行 Web 构建，再将产物复制到
`target/dx/build/auction-web-public/web/public/`，供 Public 装配根的
`rust-embed` 使用；浏览器标题由本 crate 的
`Dioxus.toml` 固定为 `Auction 公开站点`，静态入口通过 `/favicon.ico` 引用共享品牌图标；产物由
`auction-http` 内嵌进公开端二进制。未构建产物时后端仍可编译，批准的浏览器路由返回 503；未知路径保持 404，
不会被宽泛回退为 SPA 入口。

当前首页看板、lot 详情、规则文档、公开黑名单、论坛同步、竞价日志、价格历史、Public session、账户竞价/代理读取、live lot
普通出价和持久化实时事件游标页已经通过同源 HTTP 读取或提交 Public API；lot 详情现在消费完整装备安全投影，展示
分类、等级、属性、平均 roll、游戏链接和按 lot 分页的竞价历史；PostgreSQL 的目录与详情 DTO
直接提供完整 HentaVerse URL，装备名称和“在游戏中查看装备”都以该真实 URL 打开新标签，不再经过
站内跳转；SQLite Lite 隐藏空链接。P09/P11 固定 `no-store`，完整 key 不进入日志、审计、事件或
持久化缓存；公开端已补齐独立品牌导航、拍卖摘要、
状态徽章、拍卖与 lot 倒计时、竞价表单和数据/空状态视觉层；规则正文单独保持冻结的页面排版。首屏使用内联启动骨架，CSS 由静态 head 预加载，
倒计时会根据 HTTP `Date` 头估算服务端时钟，超过 24 小时按 `Xd HH:MM:SS` 展示，closing 提示在剩余 15 分钟内出现，
价格历史会把稳定的 `501 feature_not_supported` 显示为 SQLite Lite 永久能力缺失，不提供无意义的重试动作；
过期状态显示本地化的收尾文案，缺失或非法时间显示 `—`，避免客户端本地时钟偏差造成误导；生命周期已经到达
`opening` 投影时只显示本地化的“开拍处理中”，`settling`/`settled` 终态只保留状态徽章；拍品详情同样只在
拍品为 `live` 且拍卖处于 `live`/`final` 时显示结束倒计时，`sold`/`unsold` 不再把已过期时间渲染成“落锤中”；
页头实时连接徽章使用圆点、raised 背景和统一边框，并按 checking/connecting/connected/anonymous/stopped/error 状态着色；页头徽章是连接状态的唯一 live region，拍卖内容不再重复播报同一状态，也不建立第二条实时连接；
避免空白根节点和样式到达延迟造成的闪烁。会话读取失败时，开放竞价的看板会在拍品动作前显示
明确错误和原位重试，不把依赖错误折叠成匿名或静默隐藏出价入口。已认证会话会让实时页自动订阅只读 WebSocket，当前拍卖页还会订阅对应的
`auction:{auction_id}` 流，只消费安全事件信封，并在服务端要求权威快照时停止推进。加载、错误、空数据和命令确认状态均
使用五语言资源；出价、代理、登录和退出操作会锁定控件并显示明确的忙碌、成功或失败反馈。拍卖看板通过 URL 保留
`world`、`auction`、`type`、`page`，历史列表通过 URL 保留 `world`、`status`、`page`，并支持当前预览与上一轮已结算拍卖
之间的切换。页头与当前拍卖选择器只展示数据库中 enabled 的 world；价格历史、拍卖历史和 bid log
筛选器仍保留受支持但已关闭的 world，以便读取其中已经 settled 的历史。服务端同时强制
`world.enabled OR auction.status=settled`，因此 URL 不能借历史筛选值打开禁用世界的活动投影或写入。
代理表单继续支持已发布的金额缩写，普通出价使用纯数字 K 单位、最低价提示和提交前二次确认，
同时保留幂等重试、代理终态重建和最终阶段限制；实时客户端会校验事件信封、
schema、连续游标，并在断档或服务端要求时回到权威快照。公开发现范围使用持久化
`auction:discovery` 派生流，可跨进程恢复；禁用 world 的活动事件会在持久化读取边界被过滤并推进
原始高水位，已 settled 的单拍卖历史仍可 catch-up。浏览器发现游标由 Public 外壳持有，权威快照刷新导致实时 owner 重建时不会从 0 重放历史事件或形成重复连接；lot 详情、竞价历史、代理加载、规则和目录加载失败时均提供可见的原位重试；Public 进程使用持久化 relay 和有界进程内 Hub 向
WebSocket 推送，慢连接会被淘汰，客户端仍以游标 catch-up 为权威恢复路径；Public 登录页会清理一次性 key、保留 1024 字符输入边界，
按错误码和安全公开原因显示本地化反馈；需要认证的 lot/账户 CTA 会保存当前 pathname + search，
登录成功后以 replace 返回，直接打开登录页默认回到 `/`，且只接受单斜杠开头的同源路径；页头已补齐匿名登录/我的竞价入口、认证用户名和退出菜单，登录/退出会刷新账户与实时会话状态，
`/me` 承载竞价账户页，匿名时显示登录 CTA，普通竞价与代理授权使用独立分页并保留 `bid_page`/`proxy_page` URL 状态；账户 GET 固定按
`bid_page,page_size,proxy_page` 排列参数。认证页使用四列竞价表、六列代理表、账户专属样式和五语言词法，代理上限、授权历史、模式、使用次数与状态仍来自安全投影；
`/account` 保留为兼容别名并无历史记录跳转到 `/me`。当前契约没有外部广播 relay/sink；若未来新增，它属于独立扩展，
不改变当前 Public 本地 Hub 边界。`/bidlog` 使用已冻结的场次选择、页面内 world 选择、历史分页、拍品链接、代理标识、有效行高亮和移动端表格布局；论坛来源以玩家名称紧邻可点击的真实 `（#楼层）` 展示，代理来源只显示统一“代理”，不展示数字论坛账号 ID；
页码只规范化写入 `page`，仍兼容读取冻结期间产生的 `bidlog_page`，切换 world/场次/lot 时会清除
失效的下游 URL 状态。Router 首次挂载前会保留未声明的 query，同一路径前进/后退则重建路由内容并
同步页头 world，刷新、分享链接和浏览器历史都不会丢失筛选状态；真正的 SPA 换页会把键盘焦点移入
主内容，首屏挂载和同路由数据刷新不会抢焦点。`/auctions` 使用每页 10 场、轮次状态徽章以及 Lots/Bid log 直接入口；
非法 UUID 的 lot 路径在浏览器本地进入五语言 not-found，不发业务 API 请求，`/status` 继续保持
单一静态服务说明。窄屏页头将主导航折叠为带 `aria-expanded` 状态的两列菜单，刷新、语言和账户控件继续保留在独立控制区；桌面导航布局不变。
`/history` 提供 world/name/日期/价格/买家/卖家筛选、URL 状态、成交统计、拍品与拍卖链接和分页。
拍卖目录 preview/live 行新增固定顺序的 Primary Attributes 缩写；窄屏字段改为标签/内容双列网格，动作区可换行并保持足够触控高度；装备属性也在窄屏切换为
逐行字段卡片，不再依赖横向滚动。目录、历史、账户、补偿和装备属性表的长文本保持单行省略，鼠标
悬浮或键盘聚焦可查看完整值；目录装备名称同时是完整游戏 URL 链接。各表补齐本地化 caption、列
scope 与 `data-label`，不改变竞价动作契约。
普通竞价与代理弹窗提供首个输入框聚焦、Escape/遮罩关闭、`aria-modal` 内 Tab 焦点循环、
背景滚动锁定和关闭后触发按钮焦点恢复；这些是浏览器交互边界，不改变竞价命令、幂等或资格校验。
代理金额输入保留即时解析反馈，并正确区分一位和两位 `M` 小数（例如 `1.5M = 1.5M`）；
普通出价输入则只接受不带后缀的 K 单位整数，在实际发送 Credits 金额前显示独立确认步骤。超出浏览器
JSON 安全整数范围的输入会在提交前失败关闭，服务端金额与资格校验仍是最终权威。
弹窗标题携带 lot code，表单使用紧凑宽度、纵向布局、取消/提交动作组，以及带完整说明的
Fast/Slow 单选模式；最终阶段的 Slow 禁用原因通过对应控件的可访问说明公开。
登录用户的 lot 详情提供“我的代理出价”摘要，展示服务端投影的上限、模式、配额、可用动作、
完整变更历史和状态；活动授权的动作按钮明确显示为“降低代理上限”，加载失败可以原位重试。
普通竞价被服务端接受后会立即关闭弹窗并刷新权威拍卖快照；失败时保留弹窗和稳定命令 ID，
代理授权成功则继续在弹窗内展示是否领先、当前状态、配额和完整授权变更历史，权威数据刷新不会
覆盖这份命令结果，用户明确关闭后才恢复触发按钮焦点。
本 crate 只允许依赖稳定 HTTP DTO 与 `auction-web-shared`，不得导入存储、配置、凭据或管理端
组件。`src/api/` 的 HTTP/stream wire DTO 已直接复用 `auction-contracts`，只保留查询、展示和
交互状态。
