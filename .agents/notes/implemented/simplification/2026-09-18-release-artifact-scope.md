# Agent Note: 发布包收敛到正式程序与通用配置

Status: implemented

## Problem

发布脚本在普通归档中无条件加入专用测试控制脚本、安装器与配置，独立配方并未形成独立的
制品边界。用户明确要求移除整套附加内容；只删归档中的控制脚本会留下无用的安装入口，
直接删模板又会破坏首次部署配置生成时的 `include_str!` 依赖。

可选两二进制归档由 [单文件 supervisor 决定](../architecture/2026-09-20-unified-server-supervisor.md)
扩展，以下默认分体白名单、通用模板和不恢复测试安装器的理由不变。

## Decision

发布包的可执行文件仅包含 `auction-public-api`、`auction-admin-api`、`auction-worker` 和
`auctionctl`。删除专用测试安装脚本、控制 wrapper、配置目录、Just 配方、发布白名单项与
专用门禁，导航、状态说明和五语言设置文案同步移除测试档描述。

首次设置继续由 [Admin 初始化决定](../feature/2026-09-17-first-run-setup.md)拥有。
`FirstRunConfig` 直接复用公共、三角色和 runtime 通用模板，页面参数覆盖对应字段；其余数值
采用通用模板，不再维持另一份吞吐、批次和轮询 profile。生成配置仍信任 loopback 反向代理、
启用 Worker control 并注入实际服务 UID，同时去掉示例的本地邮件 `.keyenv` 路径。
origin 已由角色和 runtime TOML 拥有，删除只供安装器读取的额外文本输出。

操作者通过现有设置页或通用示例准备配置，再按部署手册准备服务账号、运行目录、systemd 和
Caddy，执行严格预检与 `auctionctl deployment`。发布指纹、双端资源隔离、白名单、权限、
确定性归档和 SHA-256 校验继续由原发布链负责；本地脏工作树产物保留 dirty 标识。

## 既有决定审计

活跃笔记中的专用测试安装包决定被本次完全吸收并删除；首次设置决定与本次部分重叠，保留
独立初始化表面的理由并互链；文档重建决定只拥有文档门禁，与本次发布范围无重叠。

旧安装层的动机是减少手工替换 origin、UID 和敏感 TOML 的漂移，并通过 systemd 总控保持
Worker → Admin → Public 的启动顺序。它曾提供保守批次、loopback metrics、250ms relay、
关闭外部写入和自动排期的单机 PostgreSQL profile；手工模式要求 root 和无符号链接、仅 owner
可读的敏感源，配置默认不覆盖，代理文件不自动 reload。这些自动装配能力随安装层删除，
权限、迁移和 readiness 约束仍由现有部署 owner 与手册承担。

旧决定不采用通用发行版安装器，因为用户、目录、升级与回滚矩阵超出单机准备范围；不以 SQLite
代替 PostgreSQL 完整档，也不绕过总控逐个启动角色；不把真实凭据装进归档或自动 reload 代理。
这些边界仍成立。旧记录的静态检查与归档核对仅证明当时制品可装配，没有真实主机、数据库、
浏览器、外部凭据或备份恢复验收证据；本次不把该历史结果当作新制品验证。

## Alternatives considered

1. **仅从归档剔除控制 wrapper。** 改动最小，也能消除额外的 bin 文件；但安装器、配置与
   文档仍保留已取消的使用入口，不能满足全部移除的范围。
2. **移动专用模板供首次设置继续使用。** 能完整保留旧批次参数，但会换一个目录继续维护
   已取消的 profile；复用通用模板能消除这份配置来源与文档负担。
3. **同时删除首次部署设置页。** 可一次移除所有模板消费者，但独立管理页设置已有单独的
   需求和 owner，超出删除附加发布内容的范围，因此只解除它对专用模板的依赖。

## Consequences

归档只暴露正式程序和通用部署资料，首次设置不再依赖专用安装目录。代价是服务账号、权限、
unit 和代理装配回到手册步骤；新生成配置中未被页面覆盖的参数跟随通用模板，已有部署配置
不被改写。如果以后再次需要自动安装，应先单独确定平台、升级及覆盖边界。

验证使用 `just verify`、Shell 静态检查、`git diff --check` 和发布构建/归档门禁，核对归档
可执行文件清单和移除项残留；不新增或运行行为测试，不启动服务，不连接数据库或执行迁移。
