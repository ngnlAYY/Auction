# Agent Note: 可选单文件服务与首次配置后启动

Status: implemented

后续 Admin 会话撤销、设置安全头/有界退出与首次迁移兼容修复见
[2026-10-03 审计修复](../bug-fix/2026-10-03-session-setup-audit-remediation.md)；保留本篇原有理由与历史验证口径。

## Problem

分体发布要求分别装配 Public、Admin、Worker；原设置页只保存配置并退出，不能完成用户要求的首次网页配置后启动体验。用户确认保留现有配置格式及默认分体发布，增加单文件分发、自管三角色子进程，并允许显式开启远程设置。

## Decision

`apps/server` 的 `auction-server` 装配根复用三个 app 的 lib 入口；角色仍在独立子进程中运行，日志、信号、HTTP 表面与业务 owner 不合并。父进程以自身可执行文件及显式 `--role`/`--config-file` 派生子进程，按 Worker → Admin → Public 等待 readiness；失败及终止时有界反序回收，不无限重启。`auctionctl` 独立，不成为 supervisor 的依赖。运行参数及部署步骤由 [server 手册](../../../../apps/server/README.md)登记。

`just release-check --single-binary` 增加可选归档，bin 白名单为 `auction-server`、`auctionctl`，输出独立的 `target/release-package-single/`。默认分体发布与 Public/Admin 资源隔离门禁不变；合并服务文件明确允许包含两个 surface，但各 HTTP router 仍只访问所属资源。单文件构建先通过分体门禁，再绑定相同 Web payload 的合并二进制；源码指纹、干净工作树、白名单、权限与归档哈希门禁不降低。

无配置目录才进入首次向导；已有、残缺或不可读取的目录失败关闭。verify 响应的 `initialize_and_start` 告知后续模式；合并 `/complete` 要求用户主动确认 `confirm_initialize=true`。保存成功只证明配置落盘，不证明后续初始化/启动成功。保存后由父进程调用存储 owner，在 SQLx 迁移锁下确认预先准备的 PostgreSQL 空库和零其他客户端，再执行追加迁移。不自动建库、不清空对象、不接管旧数据；失败保留配置及数据库现场。普通启动只验证完整 schema readiness，未通过时不启动 Worker，更不会隐式迁移。

`auction-config::managed_runtime_directory` 推导配置目录同级 `.<配置目录名>.server`，权限为 0700，拥有稳定 `owner.lock` 和 Worker control socket。生成配置沿用三角色、公共、敏感及 runtime TOML，仅覆盖运行目录、实际服务 UID/组。子进程继承部署锁；Linux parent-death signal 在父进程意外死亡时通知子进程退出。正常关闭反序 drain 总预算 135 秒，第二次信号或超时强杀，强制回收每角色最多 5 秒；合并 systemd 模板使用 `KillMode=mixed` 与 155 秒预算。初始化、迁移及启动期间使用连续信号订阅，取消后不自动进入下一阶段。

`auctionctl migrate-managed` 只针对已有合并部署，严格配置预检后取得相同独占锁才迁移；缺少锁文件、父进程或任何继承锁的角色仍存活时拒绝。普通 `migrate` 和 systemd 启动的迁移也复查合并锁，防止经旧入口与 supervisor 交错。此锁只证明本机支持的进程树所有权，不能替代数据库外部客户端或跨主机协调；合并和分体不能混合运行同一数据库。

设置默认 loopback 与一次性部署码。远程设置须同时声明允许远程、精确 HTTPS origin 和受信代理 IP；初始化表面核对 TCP peer、Host、代理提供的 HTTPS 转发头和写请求 Origin。代理必须覆盖转发头，后端端口不得直接暴露给公网；跨主机代理链路需要受信加密隧道。正常业务 Admin 不注册 setup 写接口，设置响应禁止缓存。设置页面保留密码清理、未知结果锁定与五语言文案。

## Alternatives considered

1. **单进程合并三个角色。** 可以减少 PID，但必须重写全局 tracing、信号与故障隔离；用户选择单文件自管三进程。
2. **拼接或解包三个 ELF。** 保留独立构建，却需要额外临时可执行文件及校验机制；复用 app 库并重新执行自身保持明确来源。
3. **保存配置后退出。** 风险最小，但不能满足确认后直接启动的需求；默认分体行为保留，合并入口增加受限的首次初始化。
4. **每次启动自动升级数据库。** 部署最省步骤，但会把不可逆写入变成普通重启副作用；只在首次网页确认后初始化空库，已有库仍用显式停机迁移。
5. **默认向公网开放设置。** 浏览器连接方便，但会暴露数据库与管理员凭据；远程能力仅经显式 HTTPS 代理契约开启。

## Consequences

用户可选择一个服务文件完成首次配置并启动，既有分体部署、角色配置与领域事务/幂等/审计/outbox 语义不变。代价是单文件包含两端资源、增加父进程与本机锁的运维约束；角色故障会停止整组，不支持单角色自动重启。文件锁、进程组和 parent-death signal 不能抵御特权操作者删除锁文件、任意启动隐藏角色或跨主机访问同库，部署手册明确禁止这些拓扑。

初始化只接受专用空库而不是通用升级；迁移中断可能留下部分迁移，需要备份/现场核对及显式维护，不能删除配置重跑。远程代理与后端链路安全仍需部署者正确配置，后端不自行签发 TLS 证书。保存页不会伪造 readiness，只提示查看终端并提供管理入口。

验证范围为格式、工作区及 PostgreSQL 合并入口编译、WASM、Clippy、文档/策略/i18n 和制品静态门禁。没有新增或执行行为测试，没有启动服务、连接真实数据库或宣称生产验收完成。完整进程树、信号竞态、强杀、迁移失败、远程代理及浏览器流程仍需另行授权取得运行证据；未提交工作树不能生成正式发布归档。
