## Problem

2026-09-22 对 `a463248` 源码进行模块审计，确认 29 项问题和一项论坛 DTO 省略字段问题。
问题集中在凭据撤销、异步取消、邮件资产交接、生命周期时间、Worker 领取及浏览器状态同步。
修复必须保留稳定命令与历史证据，不能把未知外部写入改为可盲重试，也不能修改已发布迁移。

持久化修正使用追加迁移。PostgreSQL `000038` 只转换从未领取、未冻结、无 delivery 的初始流拍返还，
并追加审计；有过尝试或已有外部身份的记录不转换。新周历来源属于两后端共有调度能力，历史缺失来源的
轮次和没有时区输入的手工轮次保留旧 UTC 推进语义，不使用当前配置猜测其初始意图。

真实论坛 POST 结果未知继续保持原人工核对门禁。本轮不新增自动重发机制；纯读取超时可以重试，不能清除
已经存在的未知写入事实。邮件已有历史完成账本及被错误归档的 Credits 也不自动重写，须结合远端资产人工核对。

## Alternatives considered

- 只在应用层禁止相反邮件决定：修改较少，但无法阻止并发旧快照和升级前已入队任务，因此还需存储与发送门禁。
- 把全部旧流拍 Return 改为 Send：可快速恢复队列，但会重解释已冻结身份并可能重复发送，所以只转换可证明未开始的记录。
- 后继排期继续直接加 UTC 七天：无需保存来源，但跨夏令时会改变本地钟点，因此新轮次冻结本地日历来源。
- 用新的命令 ID 重试管理写入：可以绕开冲突，却无法确定前次是否成功，因此未知结果保留完整原命令。

## Consequences

修复保护会话撤销、资产归属、幂等、时间与连续处理顺序；代价是对无法证明的历史状态保守阻断，
需要操作者核对资产和外部回执。新增迁移只随正常受控升级执行，本轮不连接数据库或执行迁移。

验证范围为完整源码差异审阅、项目静态门禁及双 WASM 编译；实际结果登记于
[实现与验证状态](../../../../docs/status.md)。遵守仓库约定，不新增或运行行为测试，不把编译通过解释为运行验收。
